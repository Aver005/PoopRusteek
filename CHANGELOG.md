## [Unreleased]

### Added

- **Установщики.** Windows: `pooprusteek-setup.exe` на Inno Setup 7 — без прав
  администратора, в `%LOCALAPPDATA%\Programs`, один экран выбора папки, PATH,
  ярлык в «Пуске», запуск в Windows Terminal, деинсталлятор с вопросом об
  удалении данных. macOS/Linux: `install.sh` (`curl … | sh`) в `~/.local/bin`
  с проверкой SHA-256, записью PATH и `--uninstall`.
- **Стабильные релизы по тегу.** `scripts/release.sh patch|minor|major` поднимает
  версию, закрывает раздел CHANGELOG, коммитит, ставит тег и пушит;
  `release.yml` собирает все платформы и публикует релиз.
- Каналы обновлений: `/update channel stable|dev` (`[update] channel`, по
  умолчанию `stable`). `stable` ставит только более новую версию, `dev` —
  сборку каждого пуша в develop.
- `pooprusteek --version`.
- Файл `LICENSE` (MIT) — лицензия была указана только в `Cargo.toml`.
- `Cargo.lock` под контролем git, CI собирает с `--locked`: релиз собирается ровно
  из тех версий зависимостей, что прошли тесты.
- Сборки для Linux arm64 и Windows arm64 (пока экспериментальные: их падение не
  блокирует релиз). Тесты в CI теперь идут и на macOS.

- Шов для родного tool-calling: `ToolCall`, `ChatMessage.tool_calls`,
  `CompletionRequest.tools`, `CompletionChunk.tool_calls` и
  `ProviderEntry.tools` (`prompt` | `native`, по умолчанию `prompt` для всех
  протоколов). Родные вызовы проходят через цикл, историю и файл сессии;
  идентификатор вызова берётся от провайдера, а не выдумывается заново.
  На проводе пока ничего не меняется: ни один провайдер их ещё не отдаёт.


- Инструмент `todo` — план для многошаговой работы. Модель присылает список
  целиком (`content` + `status`: `pending`/`in_progress`/`done`), инструмент
  проверяет его и возвращает отрисованным; при каждом обновлении список
  присылается заново и заменяет предыдущий. Своего состояния не держит: план
  живёт в истории беседы обычным результатом вызова, поэтому параллельные
  беседы и суб-агенты не делят один список. Подтверждения не спрашивает
  (побочных эффектов нет) и показывается в ленте целиком, а не выжимкой в
  200 байт. Пределы: 30 пунктов, 200 байт на пункт.
  Отдельной панели в TUI пока нет — план виден в чате как результат вызова.
- `Tool::requires_approval()` и `Tool::result_is_its_own_summary()` — два
  свойства инструмента с прежним поведением по умолчанию.
- `Expect::max_tool_errors` в сценариях харнесса: без него сценарий оставался
  зелёным, даже если каждый вызов инструмента возвращал ошибку.


- Инструменты правки файлов `edit` и `write`. `edit` заменяет точный фрагмент
  по якорю (`old_string` → `new_string`) с требованием уникальности и флагом
  `replace_all`, возвращает дифф изменённого участка; `write` создаёт файл или
  перезаписывает его целиком, создавая недостающие родительские папки. До этого
  единственным способом менять файлы был шелл (`sed`, heredoc) — ненадёжно при
  экранировании и без предпросмотра изменений.
  `edit` следует символическим ссылкам, сохраняет права файла и подгоняет
  переводы строк под файл; отказывается писать в конфигурацию самого агента и
  в MCP-конфиги; прерывается, если файл изменился с момента чтения.
  См. `.memories/JOURNAL/2026-08-29-file-editing.md`.
- Автозагрузка проектных инструкций: агент читает `POOPRUSTEEK.md` /
  `AGENTS.md` / `CLAUDE.md` / `GEMINI.md` рабочей папки. Собирается цепочка
  каталогов до корня репозитория или домашней папки (ближний файл последним),
  плюс глобальные правила из `~/.pooprusteek`. Кэш обновляется при старте, на
  `/cwd` и по `/instructions reload`.
  Текст приходит из чужого репозитория, поэтому: символические ссылки не
  разыменовываются, содержимое лежит в конверте с одноразовой меткой, а
  абсолютные правила промпта повторяются после конверта.
  См. `.memories/JOURNAL/2026-08-29-project-instructions.md`.
- Команда `/instructions [reload|on|off]` — что подхвачено, перечитать после
  правки файла, выключить.
- Секция конфига `[instructions]`: `enabled` (по умолчанию `true`) и
  `max_bytes` (по умолчанию 16 KiB на всю секцию, а не на файл).
- Чекпоинты правок и команда `/undo [list|skip]`. После каждой успешной записи
  `edit`/`write` прежнее содержимое файла сохраняется в append-only журнал в
  папке данных; `/undo` возвращает его на место после подтверждения. Файлы,
  похожие на секреты (`.env`, `*.pem`, `id_rsa`…), и файлы больше 8 МиБ не
  копируются никуда — такая правка честно помечается как необратимая.
  Откат отказывается трогать файл, изменившийся после правки: это значит, что
  его правил кто-то ещё.
  См. `.memories/JOURNAL/2026-08-29-checkpoints.md`.

### Changed

- **Самообновление берёт версии, а не каждый коммит.** Раньше `/update` ставил
  любую сборку из develop при несовпадении хэша и мог откатить на старую.
  Теперь каждый релиз несёт `manifest.json` (версия, тег, хэши), а канал
  `stable` сравнивает версии. Rolling-релиз develop переехал с тегов
  `latest`/`vX.Y.Z-dev` на тег `dev`; `latest` обновляется только стабильными
  релизами — чтобы сборки ≤ 0.1.0 перешли на новый обновлятор.
- После самообновления версия в «Приложениях» Windows обновляется вместе с
  бинарником.
- `--debug-log` и `/debug` в release-сборке пишут в папку данных, а не в
  `.dev/` текущей папки.
- **Разрешения инструментов стали гранулярными.** Правило теперь это инструмент
  плюс область: `bash · cargo test` разрешает только команды, начинающиеся с
  этих слов, `edit · <папка>` — только запись в неё. Модалка подтверждения
  показывает три варианта списком — «только сейчас» (по умолчанию), «всегда для
  этой области» и «всегда для инструмента целиком» с пометкой опасности, —
  вместо прежнего одного флажка «always allow».
  Составную команду (`&&`, `;`, `|`, `$(…)`, перенос строки) сузить нельзя:
  область для неё не выводится вовсе, потому что `git status && rm -rf /`
  начинается с `git status`, а делает совсем другое. Пути к файлам
  нормализуются перед сравнением.
  Старый `whitelist.json` (массив имён) читается по-прежнему и переносится как
  «инструмент целиком», но теперь с уведомлением: широким это разрешение стало
  не по выбору человека. Нечитаемый файл отставляется в `whitelist.json.bad`
  вместо молчаливой потери.
  См. `.memories/JOURNAL/2026-08-29-granular-whitelist.md`.

- Модалка подтверждения инструмента показывает читаемое превью вместо сырого
  JSON: для `write` — содержимое настоящими строками, для `edit` — готовый
  `-`/`+` дифф, плюс пометка `OUTSIDE WORKSPACE` для путей вне рабочей папки.
  Раньше `serde_json` экранировал переводы строк, файл схлопывался в одну
  строку, а попап по ней не рос и не прокручивался.
- Подпись «Always allow for this session» исправлена: разрешение пишется на
  диск и переживает перезапуск.
- `read_file` разворачивает `~`, как `edit` и `write`.

### Fixed

- **Безопасность:** запрет на запись в конфигурацию агента обходился путём через
  несуществующую папку и `..` (`проект/нет/../../<данные>/whitelist.json`) на Linux
  и macOS — запись сама создавала недостающую папку, и `..` уводил её в охраняемую.
  Нашёлся первым прогоном тестов на macOS.
- **Release-сборка больше не подменяет промпты и wasm файлами с диска.**
  Системный промпт, встроенные навыки и солвер PoW искались сначала в текущей
  папке, рядом с exe и по пути сборки, зашитому в бинарник. Запуск из
  папки с `assets/prompts/…` молча менял промпт. Теперь с диска читает только
  debug-сборка, и только из исходников.

- Сборка проходит clippy 1.98: `chunks_exact` с константой заменён на
  `as_chunks` (три места), а крупный `Err`-вариант HTTP-хендлеров убран в
  `Box`. Линты появились в 1.97/1.98, локальный тулчейн отставал, поэтому
  pre-commit был зелёным, а CI падал.

- Ход с вызовом инструмента больше не падает на строгих OpenAI-совместимых
  эндпоинтах. Результат инструмента уходил как `role: "tool"`, хотя у
  ассистентского сообщения перед ним не было и не могло быть `tool_calls`;
  api.openai.com и шлюзы отвечают на это 400. Теперь результат уходит
  пользовательским текстом — так же, как в Anthropic- и Gemini-путях.
  Локальные серверы (LM Studio, Ollama) это прощали, поэтому баг не был виден.
- Встроенный OpenAI-совместимый сервер принимает `"content": null` в
  ассистентском сообщении. Раньше на таком теле падал разбор целиком и клиент
  получал «400 invalid request body» — а именно так выглядит история любого
  клиента, который переигрывает свои же вызовы инструментов.


- Ответ, обрезанный провайдером по лимиту токенов (`finish_reason: length`)
  или фильтром, больше не выдаётся за ошибку стрима. Стоп-сигналом считалась
  только причина `stop`, поэтому готовый, но неполный текст выбрасывался, а
  человек получал «Stream ended without stop signal». Теперь текст доходит, а
  над ним появляется пометка, что ответ неполный. Задевало только
  OpenAI/Anthropic/Gemini-провайдеров: DeepSeek шлёт лишь `stop`.


- Промпты `refactor.prompt.md` и `poet.prompt.md` советовали несуществующие
  инструменты `file.edit` / `file.read` и правку файлов через `Set-Content`.
- **Безопасность:** запрет на запись в конфигурацию самого агента не работал
  для файлов, которых ещё нет. У несуществующей цели канонизация пути падала,
  и сравнение уходило на сырой путь с другим префиксом. На свежей установке
  модель могла записать себе `whitelist.json` с авто-одобрением всех
  инструментов. Сравнение путей вынесено в `src/safe_write.rs`: канонизируется
  ближайший существующий предок, сравнение идёт по компонентам.
