# 01 · Критика UI и целевой макет

Снимки: `E:\Projects\Me\pooprusteek\.dev\research\ui\baseline\` (26 кадров из тестового бэкенда + 3 живых из conhost).
Инструмент: ветка `chore/tui-capture` в worktree `D:\Worktrees\pooprusteek\t3-67311312`.

Главное в трёх строках:
1. Ввод внизу — это не только «передвинуть поле». Сейчас у главной и у чата **два разных скелета** (`landing.rs` и ветка чата в `draw_frame`). Нужен один скелет, где ввод всегда на одной строке снизу.
2. «Идущая работа» в чате фактически **не нарисована**: запущенный инструмент, суб-агенты, фоновые процессы видны только как обрезанная строка в статус-баре (`reduce.rs`: `ToolStarted` не меняет историю). Это главный пробел.
3. Правая панель на 34 колонки статична (модель, сессия, `Rate: off`), съедает 42% ширины на 80 колонках и не показывает ничего живого.

## 1. Как снимать экран (выбор и проверка)

| Вариант | Результат на этой машине |
|---|---|
| **b) `TestBackend` → HTML → PNG (Chrome headless)** | **Выбран.** Рисует настоящий `draw_frame`, данные зафиксированы, два прогона дают побайтно одинаковый текст (проверено на 10 кадрах чата). Работает за ~4 с + ~1 с на PNG. |
| a) настоящий бинарник в conhost + `CopyFromScreen` | **Работает** (окно видно на рабочем столе сессии 1, `SendKeys` вводит текст), но недетерминирован: время, размер окна (conhost дал 974×678 px вместо 120×40 ячеек, правый край обрезан), забирает фокус. Оставлен как дополнение для того, чего бэкенд не покажет: **шрифт и пропавшие глифы** (см. B5). |
| c) ConPTY + эмулятор терминала | Не делал: дороже, а `TestBackend` уже даёт тот же буфер, что уйдёт в терминал. |

Что даёт (b) и чего не даёт: цвета, рамки, раскладка, переносы — точно те же, что в приложении. Не показывает: как конкретный шрифт консоли рисует глифы (это ловит (a)) и анимацию (кадр = один тик, `animation_tick = 7`).

Что сделано в коде (минимум, коммит ниже):
- `src/tui/render/mod.rs`: тело кадра вынесено из `render()` в `draw_frame(frame, state, config) -> Option<(u16,u16)>`; `render()` теперь только заголовок окна, курсор и вызов. Поведение то же.
- `src/tui/capture.rs` (`#[cfg(test)]`, тест `#[ignore]`): сцены, размеры, темы; на каждый кадр `.html` (цвета, по ячейке на символ, сетка 10×20 px) и `.txt` (для чтения и диффа).
- `scripts/tui-capture.ps1`: сборка → тест → PNG. `scripts/tui-capture-real.ps1` + `scripts/ui-capture/*` (одноразовый конфиг и мок-скрипт) — живые снимки.

### Грабли окружения (на этой машине)
- **Нужен MSVC 14.50 из `H:\VS Build Tools`.** В VS 2022 (14.41) ort не линкуется: `LNK2001 __std_find_end_1`. Скрипт сам подхватывает `vcvars64.bat` оттуда (или из `$env:VCVARS64`).
- В Git Bash `link.exe` — это GNU `link` из `Git\usr\bin`, cargo падает с `link: missing operand`. Собирать надо из PowerShell/cmd с vcvars.
- **Pre-commit хук из Git Bash не может слинковать тесты** (git сам ставит `Git\usr\bin` первым в PATH). Я коммитил с `CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_LINKER=<путь к link.exe 14.50>`, хук не обходил.
- Clippy 1.99 на тестовых целях даёт 11 ошибок в чужом коде (`items after a test module` и др.); хук проверяет только `--bin`, там чисто. Мой единственный хит (`no_effect_replace`) исправлен.

## 2. Что вижу: критика

Числа ниже — из кода и снимков; контраст посчитан по WCAG для всех 10 пресетов.

### 2.1 Иерархия и скелет
- **Два скелета.** Главная: логотип 3 строки + ввод 4 + рамка + подсказки + таблица, всё по центру (`landing.rs::render_landing`, `top_pad = (h − center_h)/2`). Чат: `[chat Min(1), sep 1, ввод 4, рамка 1, статус 1]` (`render/mod.rs`). После первого сообщения ввод «прыгает» с середины на низ — именно то, что не нравится.
- **Служебные строки.** В чате 7 строк обвязки на 24 строках экрана остаётся 17 строк под переписку (разделитель + верхний отступ ввода + нижняя рамка — три чисто декоративные).
- **Живое состояние невидимо.** Идёт ход, запущен `bash`, два суб-агента, фон, GOAL, таймер — а в переписке этого нет. Всё это уплотнено в строку статуса: `GOAL:build DeepSeek · deepseek-chat · deepseek-chat mcp:2/3 bg:2/1i/1p agents:2 ⏰:1 … \ Running bash... (1840 tok, 47.0s, 39 t/s) GOAL:iter#2 msgs:7 tot:159 | Nov 06 14:02`. Это ≈130 знаков в строке в 120 колонок.
- Правая панель: статичные факты (Provider, Session, Rate, Started, Latest, Messages) — информация «на раз», а не «пока работаю». Живого там только `Speed` (на кадре — `◐`) и счётчики.

### 2.2 Плотность и отступы
- Панель фиксированно 34 колонки: на 80 колонках это 42% ширины, на переписку остаётся 43 колонки, вывод инструментов рвётся на обрывки (`chat-working__default__80x24`), а сама панель обрезана по высоте (`Activity` не помещается). Порог «панель есть, пока чату ≥ 24 колонок» слишком низкий. На 200 колонках — наоборот: строки чата по 160 знаков (плохая мера чтения), панель 17%.
- Текст чата начинается в колонке 0, без левого поля; первая строка панели прижата к верхнему краю экрана.
- У каждого инструмента три разноцветных плашки подряд: зелёная `✓`, синяя с именем, серая `done`, плюс заливка тела. Плашка заголовка ответа (`pooprusteek (deepseek-chat)`) — ещё одна заливка. Шум выше, чем полезная информация.

### 2.3 Цвет и контраст (посчитано)
- `text_dim` на фоне ниже 4.5:1 в **8 из 10** пресетов: default 5.4, catppuccin 3.4, dracula 3.0, gruvbox 3.0, nord **2.4**, tokyo-night 2.8, rose-pine 3.4, synthwave 3.3, matrix 4.3, paper 3.1. На заливках сообщений хуже: `text_dim` на `tool_bg` у nord **1.7**, на `user_bg` у dracula 2.3. Этим цветом рисуются метки времени, токены, «done», подсказки — то есть именно то, что читают.
- `input_bg` против `bg`: 1.03–1.11 — поле ввода почти не отличается от фона (default 1.06). Рамки (`border`/`bg`) 1.2–1.6.
- Выделенная строка в `/providers` и `/mcp` — яркая заливка `accent` с серым текстом: `text_dim` на `accent` 1.4–3.5 (default 1.4). На снимке строка `lm-studio` читается с трудом.
- Тема `matrix`: плашки «успех» и «имя инструмента» одного оттенка, статус `✓` не отличается от имени; `tool_bg` почти фон.
- Тема `paper` (светлая) в целом читаема, слабые места — те же `text_dim` (3.1).

### 2.4 Рамки и модалки
- Подтверждение инструмента (`render_tool_approval`): аргументы не переносятся и обрезаются по ширине рамки (`... --nocaptur`). Человек подтверждает команду, которую не видит целиком — это не косметика, а вопрос безопасности. Подтверждено и на 120×40, и на 80×24, и в живом conhost.
- Фон под модалкой не затемняется: панель, текст чата и модалка спорят за внимание.
- Между аргументами и вариантами «Just this once / Always» пустая полоса на 8 строк (`fill_panel_space`), при этом для длинной команды места нет.
- Автодополнение `/` (`render_autocomplete`) ложится поверх последних строк чата и вплотную к ввода, перекрывает разделитель. Заголовок «Commands» — закрашенная вкладка, не такая, как у других окон. В строке команды `/help` и в колонке usage повторяется то же `/help`.

### 2.5 Статус-бар
- Приоритета при нехватке места нет: `status_bar_gap` лишь делает `.max(1)`, поэтому на 120 колонках при работе центр обрезается («`(1840 tok, 47`»), а **правая часть (GOAL, msgs, ctx, время) пропадает**; на 80 колонках режется уже левая.
- Дубли: `deepseek-chat · deepseek-chat` (модель из конфига и `last_model`), GOAL показан слева (`GOAL:build`) и справа (`GOAL:iter#2`); «session label» — это просто дата `Nov 06 14:02`.
- Загадочные сокращения: `bg:2/1i/1p`, `agents:2`, `⏰:1`, `tot:159`.
- Спиннер `| / - \` (ASCII) в статус-баре и `◐` в панели — два разных, при этом панель и статус показывают скорость в разных местах.

### 2.6 Индикация работы
- Нет строки «что сейчас делается»: инструмент, аргумент, время, суб-агенты. `AgentEvent::ToolStarted { name }` несёт только имя и в историю не попадает.
- Пока идёт ход, поле ввода выглядит живым, но: **каретки нет** (`cursor_pos_inner` возвращает `None`, пока `generation.active`), а **Enter молча ничего не делает** (`keys/chat.rs`: `Enter if !generation.active`). Очереди сообщений нет, подсказки нет.

### 2.7 Узкое окно
- ≤ 60 колонок панели нет, поле и переписка читаемы; остальное — как на 80, но без проверки вплоть до 40. На 60×20 строка статуса уже режется после `agents:`.
- На 80 колонках панель обязана быть выключена по умолчанию.

### 2.8 Консистентность
- Заголовки окон: у `/providers`, `/mcp`, `/themes` двойная рамка (заголовок + подвал), у модалок одинарная с цветным заголовком, у автодополнения закрашенная вкладка — три манеры.
- `/mcp`: колонки заголовка (`TYPE`, `TOOLS`) не совпадают с колонками значений (`stdio 2t` слипается, `TOOLS` стоит правее значений), снизу пустой экран.
- `/themes`: описания в галерее режутся посреди слова без многоточия.
- Главная: колонка id в «Recent sessions» — обрезанный штамп `2026-11-05T09-1…`, дублирующий соседнюю колонку даты; модель обрезана до `[deepseek-reaso…`.
- Markdown: **таблицы выводятся как строка `Слой | Было | Стало | парсер | …`** без выравнивания (в `markdown.rs` таблицы включены, но рендер плоский); цитата рисуется как `|`; блок кода — без рамки и подписи языка; список задач `* [x]` вместо чекбокса.

### 2.9 Что хорошо (сохранить)
- Единая палитра ролей (`Theme`, 17 ролей) и живой предпросмотр тем — сильная часть.
- Мини-превью темы в галерее; список сессий на главной; модалка выбора модели с фильтром; видно варианты «Just this once / Always: scope» (сильная часть, `Grant`).
- Кадры чата быстрые (кэш строк, `render_chat_perf_probe`) — переделка раскладки их не ломает.

## 4. Сравнение с лучшими практиками (только проверенное)

Проверить удалось мало: поиск вернул в основном сторонние сводки, не официальные страницы.

- **Поле ввода внизу, статус рядом.** Для Codex CLI сторонние сводки описывают композер как область ввода внизу TUI и настраиваемый нижний `status_line` (`model, context_usage, cwd, spinner`) — [сводка](https://codex.danielvaughan.com/2026/05/05/codex-cli-tui-customisation-keymaps-themes-status-lines/). Для Claude Code — пользовательская строка статуса внизу, скрипт получает JSON (модель и пр.) — [статья](https://alexcloudstar.com/blog/claude-code-status-line-guide-2026/). Из официальных страниц я это **не подтверждал**.
- **opencode.** По документации контент по умолчанию центрируется с отступами, `"layout": "stretch"` растягивает на всю ширину — [docs](https://opencode.ai/docs/tui/) (через зеркало, сверять с оригиналом). Про расположение поля на домашнем экране я **не смог проверить**.
- **Остальное — предположение, не проверено**: у lazygit/gitui/helix рабочая зона разбита на панели с рамкой активной, строка состояния — одна, внизу, с режимом слева и позицией справа; цвета выбора строки — фоновая заливка с сохранением цвета текста. Это общее знание, а не результат проверки.

Выводы, которые держатся и без сравнения: одна строка статуса с приоритетом сегментов; живое состояние рядом с вводом; активность не в боковой панели, а там, где смотрит глаз.

## 5. Целевой макет

### 5.1 Области (один скелет для главной и чата)

```
┌ transcript ───────────────────────────────────────────┐ ┌ sidebar (опц.) ┐
│  (Min) — история; на главной здесь «приветствие»       │ │ ≥140 колонок,  │
│                                                       │ │ по хоткею;     │
├ dock (0..4 строки, только пока идёт работа) ──────────┤ │ 30 колонок     │
│  что делается сейчас, суб-агенты, фон, GOAL           │ └────────────────┘
├ composer ─────────────────────────────────────────────┤
│  правило-заголовок (1) + ввод (1..5, растёт)          │
├ footer (1) ───────────────────────────────────────────┤
│  подсказка клавиш | модель · mcp · ctx · время        │
└───────────────────────────────────────────────────────┘
```
Инвариант: `composer.y + composer.height + footer.height == H` на любом размере и на любом экране (главная, чат). Это легко проверить тестом `TestBackend`.

Обвязка в простое: 3 строки (правило + 1 строка ввода + footer) против 7 сейчас → на 24 строках 21 строка под переписку вместо 17.
