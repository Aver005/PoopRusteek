## HIGH


### Announcing work ends the turn as if it were done

A turn whose final reply is plain text and no tool call is treated as a
finished answer. The model frequently uses that shape to *announce* the next
step instead of answering: given an empty directory and "create three files",
a live run did `ls -la`, replied "Директория пуста, только .gitkeep. Создам три
файла." and stopped. The harness scored it `completed` with an empty workspace;
a user would see a confident message and no files.

Reproduce: `sandbox/scenarios/dev/greenfield-todo-page.toml`, which fails on
the file expectations rather than on the answer text.

Not obviously a code bug — the loop cannot read intent — so the first thing to
measure is whether the system prompt can remove the behaviour ("never end a
turn by announcing work you have not done"). A loop-side nudge on
announcement-shaped endings is the fallback, and needs the harness to show it
does not cost anything elsewhere.

## RESOLVED / MOOT

- ✅ **`/compact` had no guard against a running turn or a second `/compact`, and `CompactFinished` overwrote the history wholesale** (found 2026-08-26 by the five-agent compaction review, fixed the same day). The task rewrote a *snapshot* of the history taken at spawn time, so anything the user or a live turn added while the summariser ran was destroyed on arrival. Now `Conversation.compacting` holds the snapshot length: `spawn_compaction` refuses while the chat is streaming or already compacting, `end_compaction`/`swap_compacted` splice the newcomers onto the rebuilt history and refuse the swap outright if the history shrank underneath, the `JoinHandle` is stored so Ctrl+C/Esc can abort the run (which then reports "cancelled" rather than applying stale messages), and `swap_compacted` refreshes `context_used` so the indicator matches the new history. `→ src/app/conversation.rs` (`begin_compaction`/`end_compaction`/`swap_compacted`), `src/app/multichat.rs` (`spawn_compaction`), `src/app/mod.rs` (`CompactFinished`)
- ✅ **A failed rung-1 spill was silent, and the loss reached the saved session** (same review, same day). `clear_tool_bodies` replaced the body with a marker naming a file that had never been written — the model was told to `read_file` a path that did not exist, and the original output was gone from history for good. Now the spill task returns the indices it actually wrote, only those bodies are replaced, and `context.prune` carries `spill_failed=N`. Regression: `a_body_whose_spill_fails_is_never_replaced_by_a_marker`. `→ src/agent/runner.rs` (`clear_tool_bodies`)
- ✅ **Rung 2 cleared tool bodies *before* deciding whether the re-seed was worth it** (same review, same day), so both refusal paths — "still over usable" and a failed `reset()` — destroyed history for nothing, on a provider where a cleared body is never re-sent. The project's own test asserted that behaviour. Now the decision runs on a prospective estimate built from the pure `plan_prune`/`freed_tokens`/`marker_tokens` (nothing touched), and `clear_tool_bodies` runs only after `reset()` succeeds; the test is inverted to `assert!(!dir.exists(), "nothing may be spilled on the refusal path")`. `→ src/agent/runner.rs` (`reset_server_session`)
