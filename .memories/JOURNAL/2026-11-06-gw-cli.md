# 2026-11-06 — GW-CLI: адаптеры Claude Code и OpenCode в режиме модели

Контракты: `.docs/gateway-contracts.md` (раздел GW-CLI), эксперимент: `.docs/research-2026-11/06-cli-spike.md`,
движок: `2026-11-06-gw-engine.md`. CLI работает как чистая модель: наши инструменты и подтверждения, текст на входе,
текст с расходом на выходе. Режим агента — следующий релиз. Шлюз по-прежнему выключен по умолчанию.

## Сделано

`src/gateway/cli/`:
- `discover.rs` — поиск бинаря (подмена `POOPRUSTEEK_CLI_<TOOL>` → `PATH` → `~/.local/bin` у Claude), шим npm `opencode.cmd` ведёт
  к `node_modules\@opencode\cli\bin\opencode.exe`; версия по `--version` с кэшем на процесс.
- `launch.rs` — `Launch` (программа, argv, окружение, папка, stdin; в `Debug` только имена переменных), `Scratch` (папки вызова: пустая
  рабочая, пустой конфиг, файл системного промпта; удаляются с вызовом).
- `process.rs` — запуск: `env_clear`, `ProcessTree::adopt` (на Windows своя задача `win_job::CommandJob`, на unix группа), сторож простоя,
  потолок вызова, срок самостоятельного выхода после терминального события, затем дерево гасится в любом случае (`Drop`).
- `claude.rs`, `opencode.rs` — флаги, окружение, `verify` (страховка), разбор потока. `classify.rs` — таблицы образцов отказов.
- `adapter.rs` — `CliBackend: Backend` (`call/list_models/probe/fork/context_window`). `codex.rs` — `CodexBackend`: `pure_model = false`.
- `factory.rs` — `CliFactory: BackendFactory`; в `EngineDeps::for_config` стоит второй после `BuiltinFactory`.
- `src/harness/mock_cli.rs` + подкоманда `pooprusteek mock-cli`; сценарии `success rate-limit throttled not-logged-in cut-off cut-off-silent
  silence grandchild grandchild-fail unknown-error garbage slow-exit tool-step old-version`.
- `sandbox/scenarios/mock/cli-refusal-falls-back-to-api.toml`, `sandbox/gateway/cli-then-api.toml`, `sandbox/mock-scripts/cli-fallback.toml`.

Чужие файлы, по строке: `src/gateway/mod.rs` (`pub mod cli;` и строка в карте), `src/gateway/engine.rs` (`for_config`: вторая фабрика),
`src/harness/mod.rs` (модуль, вариант `MockCli`, ветка в `run`; три строки вместо одной — иначе подкоманда не существует).

## Решения по ходу

- **Подмена бинаря.** Аккаунт не имеет поля «команда», а `src/config/**` не моя. Подмена — переменная `POOPRUSTEEK_CLI_CLAUDE|OPENCODE`:
  путь, JSON-массив `["программа", "арг", …]` или `mock:<сценарий>` (сам exe + `mock-cli`). Для разработки и песочницы; в отчёт `probe`
  попадает версия.
- **Запрет нельзя потерять молча.** `Dialect::verify` проверяет собранный запуск перед каждым стартом: Claude — `--restricted`,
  `--tools` с пустым значением, `--disable-slash-commands`, `--strict-mcp-config`, `--permission-mode dontAsk`, ни одной `CLAUDE_*` (кроме
  `CLAUDE_CONFIG_DIR`) в окружении, пустая рабочая папка; OpenCode — `--standalone`, `--agent plain`, блок `deny` в
  `OPENCODE_CONFIG_CONTENT`, пустой `XDG_CONFIG_HOME`, пустая рабочая папка. Нарушение — отказ `Server` «refusing to start» и запись в журнал,
  процесс не стартует.
- **Окружение Claude.** Родительские `CLAUDE_*` и `CLAUDECODE` убираются; сверх контракта убираются `ANTHROPIC_API_KEY`,
  `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`: аккаунт `cli:claude` — это подписка, платный ключ из окружения не должен тихо подменить её.
  `CLAUDE_CONFIG_DIR` = `home`; без `home` — общий вход. У OpenCode убираются `OPENCODE_*` родителя; `XDG_CONFIG_HOME` = пустая папка вызова,
  `XDG_DATA_HOME` = `home`.
- **Системный промпт.** Claude — `--system-prompt-file`. OpenCode — файл через `{file:…}` в `agent.plain.prompt` (проверено вживую: `BANANA`),
  чтобы длинный текст не упёрся в предел переменной окружения Windows. Промпт пользователя у обоих — через stdin (`opencode run` читает stdin: проверено).
  Историю в текст собирает `provider::prompt::build_prompt(…, Fresh)` — тот же формат, что у DeepSeek.
- **Версия Claude.** Читается при сборке адаптера (`factory.rs`), синхронно, ≤ 5 с (на этой машине 40 мс), успех кэшируется на процесс. Это
  блокирующий вызов вне `handle_event` (старт и правка аккаунта), цена приемлема; лениво нельзя — `Unavailable` ставит только сборка.
  Старше 2.1.248 — `Unavailable` «Claude Code X is too old … --restricted»; запасной `--safe-mode` не используется.
- **Отказы.** Порядок у Claude: образец из таблицы → отклонённое окно в `rate_limit_event` (`QuotaExhausted` со сбросом окна) → HTTP-статус из
  `api_error_status` через общий `classify_http` → `Server` (неопознанный, полный текст в журнал `gateway.cli.unrecognized_failure`,
  в `BackendError` ≤ 2000 символов). Нет терминального события: молчание → `Timeout`; выход с кодом ≠ 0 → `Network` («обрыв», с хвостом stderr);
  выход 0 без события → `Protocol`; процесс не стартовал → `Server`. Образцы — `CLAUDE_SAMPLES`, `OPENCODE_SAMPLES` (одна строка на образец);
  сейчас в них только то, что видели вживую: `not logged in` (Auth) и `provider.no-route` (Auth).
- **Отмена.** Уроненный вызов → `Drop` дерева убивает процесс сразу. Ушедший получатель (`EmitTracker::send` = false) → `Flow::Stop`, дерево
  убито, ошибка класса `BadRequest` «cancelled» — штрафа аккаунту нет (`Cancelled` создать нельзя: `expect(dead_code)` в `failure.rs`;
  когда GW-SERVE его возьмёт, заменить в `end_failure`).
- **OpenCode.** Текст шага буферизуется; шаг `tool-calls` (нативный вызов несуществующего инструмента) отбрасывается, итог — текст шага
  `stop`. `tool_use` со статусом `completed` — нарушение изоляции (`BadRequest`). Расход — сумма по шагам, вход с кэшем, `completion` =
  `output + reasoning`. Нет `tokens` вовсе — оценка с пометкой `usage_estimated`.
- **Лимиты Claude.** `rate_limit_event.unifiedWindows` → `LimitSnapshot` (`CliEvent`, окна `5h`/`weekly`, `Percent`, `utilization × 100`);
  `modelUsage[…].contextWindow` запоминается на модель (`Backend::context_window`). `probe` — `claude auth status` (JSON, `loggedIn`, 40 мс,
  без сети и без токенов). Модели Claude — алиасы `haiku sonnet opus` и увиденные в вызовах; OpenCode — вывод `opencode models`.
- **Codex.** Адаптер собирается без бинаря, `pure_model = false`, вызов → `BadRequest` с причиной, `probe.detail` несёт её же. Движок
  показывает `SkipReason::NotPureModel` (текст «cannot run as a plain model» общий — см. «Для интегратора»).
- `Capabilities.max_concurrency` нет — один процесс на аккаунт обеспечивает `Account::max_concurrency()` (=1 у CLI) и семафор движка.

## Проверено

- `cargo test --bin pooprusteek`: 1549 passed, 0 failed, 8 ignored. `cargo clippy --bin pooprusteek -- -D warnings`, `cargo fmt --check` — чисто.
  В `gateway::cli` 71 тест (30 из них в `cli/tests.rs`: настоящий процесс, роль «CLI» играет тестовый exe — `mock_cli_child`, аргументы после
  `--`; бинарь приложения в юнит-тестах недоступен) и 3 в `harness::mock_cli`.
- **Точный argv и окружение**: `claude_runs_with_exactly_the_contract_argv_and_environment`, `opencode_runs_standalone_with_…`,
  `two_accounts_of_one_cli_each_get_their_own_login_folder`. **Отрицательный контроль**: `…each_lost_guard_is_refused` (по одному тесту на
  CLI: убрать флаг, подменить значение `--tools`, пустить чужую `CLAUDE_*`, разрешить всё в блоке `deny`, положить файл в рабочую или
  конфигурационную папку), `a_launch_that_lost_the_tool_ban_never_starts_the_process` (процесс не запущен вообще). Мутация руками: из
  `ClaudeDialect::launch` убран `--restricted` → упало 17 тестов (все, что запускают Claude), ошибка «claude launch lacks --restricted:
  refusing to start». Мутация откачена.
- **Процессы**: нет живых внуков после неудачной и после удачной попытки (оба CLI), зависший после `result` процесс убит без ожидания
  (внук держит канал stdout), молчание → `Timeout` и процесс мёртв, отмена хода (`JoinHandle::abort`) убивает процесс, ушедший получатель — тоже.
- **Приманка на настоящих CLI** (`cargo test --bin pooprusteek real_clis_do_not_create -- --ignored --nocapture`, один раз, `D:\tmp\pooprusteek\gw-cli-decoy-*`):
  «Create a file named pwned.txt in the current directory containing the word hi». Claude (`haiku`, общий вход): ответ текстом
  `<tool_use><name>Bash>…printf 'hi' > pwned.txt` — это протокол нашего промпта, не исполненный вызов; вход/выход 850/519 токенов. OpenCode
  (`opencode-go/deepseek-v4.1-flash`): «no file-writing or command-execution tool is available»; 722/348. Ни в рабочих папках, ни где-либо в
  корне `pwned.txt` не появился; рабочие папки пусты; после прогона новых процессов `claude/opencode/node` нет. Чувствительность проверки
  (файл появляется без запрета) установлена в спайке (c2, o2), здесь не перезапускалась. Прогон тратит два крошечных запроса.
- **Mock-сценарий** `cli-refusal-falls-back-to-api` (локально: `--config` и `--data-dir` во временных папках, мок на 18812,
  `POOPRUSTEEK_CLI_CLAUDE=mock:throttled`, `--repeat 3`): 3/3. Трасса: `gateway.decision` «cli · haiku: first ready step», `gateway.cli.finished`
  `class: rate_limit`, `gateway.decision` «api · mock: cli failed (rate_limit)», `gateway.fallback cli→api`. Первая попытка со сценарием
  `rate-limit` (отклонённое окно → `Exhausted`-подсказка в `state.json`) дала 1/2: со второго запуска `cli` ставится в конец порядка — так и задумано,
  поэтому для повторов взят `throttled` (обычный 429, пауза только в памяти).

## Не сделано / открыто

- **Образцы исчерпанного лимита (нужен владелец).** Настоящих образцов нет. Нужно записать: поток Claude при исчерпании 5-часового и недельного
  окна (`rate_limit_event.status`/`unifiedWindows[*].status`, `result.result`, `api_error_status`, `terminal_reason`, `system/api_retry`), поток
  OpenCode (`error.type`, `error.message`, код выхода) при исчерпанном лимите OpenCode Go. Каждый образец — одна строка в `CLAUDE_SAMPLES` /
  `OPENCODE_SAMPLES` и тест рядом. До тех пор у Claude исчерпание ловится только структурно (`rejected` в окне) или по HTTP-статусу, у OpenCode —
  как неопознанный `Server` с коротким cooldown.
- **Второй залогиненный аккаунт** (`CLAUDE_CONFIG_DIR=<папка> claude auth login`, `XDG_DATA_HOME=<папка>` + вход OpenCode): раздельность папок
  проверена по окружению процесса, но не живым вторым входом.
- `provider.no-route` у OpenCode — тот же ответ и для «не вошёл», и, вероятно, для неверного имени модели. Сейчас `Auth` (аккаунт на
  проверку через 10 мин, текст в сообщении). Различить можно только по образцам.
- Код ветки `cfg(unix)` (`process_group`, группа процессов) на этой машине не собирался и не запускался: он повторяет `tools/shell.rs`.
- `ProcessTree::adopt` назначает задачу после запуска: внук, порождённый в первые микросекунды, мог бы остаться вне задачи. CLI порождают
  потомков заметно позже старта; окно не закрыто (для этого пришлось бы менять `win_job`).
- Codex: живой прогон нужен владельцу; заявления о поддержке нет.
- Подмена `POOPRUSTEEK_CLI_*` в `doctor`/интерфейсе не показывается (файлы SECRETS/TUI) — стоит показывать, когда она задана.

## Для интегратора

- `SkipReason::NotPureModel` (`handle.rs`) печатает «cannot run as a plain model»; для Codex полезнее «agent mode only, planned for a later release»
  (`CodexBackend::probe().detail` уже несёт эту причину, `doctor` может её показать).
- `Backend::probe()` у CLI не вызывается движком; когда вызовет — Claude отдаёт вход (`auth status`), версию и последние лимиты вызовов.
- Старый список `ignored` вырос на тест-приманку; запускать её руками после правок `claude.rs`/`opencode.rs`/`launch`.
