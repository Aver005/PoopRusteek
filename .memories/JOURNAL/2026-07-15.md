# 2026-07-15 — Quality/structure audit (no code changes)

**What**: Full-codebase quality audit — bad practices, dead code, excessive
branching, duplication, overloaded modules — focused on everything added since
the 2026-07-04 cleanup pass (server gateway, semantic layer, compat provider
trio, themes, model_cache, self-update, paste/mouse/search) plus regrowth of
previously-split files. Method: 7 parallel subsystem sweeps + lead
verification of every top finding + mechanical metrics (clippy
`cognitive_complexity`/`too_many_lines`, LOC, invariant greps). Read-only:
**no source files were changed**.

**Output**: `reference/AUDIT-2026-07-15-QUALITY.md` (full ranked findings,
verified/reported status, execution order). New defects cross-filed in
`BUGS.md`; stale BUGS entries corrected (PoW spawn_blocking — fixed 07-04;
hardcoded theme — fixed 07-05).

**Headlines**:
- One real event-loop invariant violation: `keys/mcp.rs` `'d'` arm holds the
  MCP manager lock across `remove_server().await` inline (siblings spawn).
- MCP stdio children are NOT in the Windows Job Object (`win_job` covers only
  tools/background) — force-close orphans MCP server processes; the 07-07 fix
  never reached this sibling.
- Largest dedup: `openai/anthropic/gemini_client.rs` are near-identical
  (~170–180 lines ×3 → ~150–200 lines removable via a protocol-hook trait).
- `run_agent_loop`: 513 lines, CC 42, **14 positional args** while `TurnSpec`
  exists — `AgentRuntime::spawn` unpacks the spec it was built to encapsulate.
- `app/events.rs` (1440) mixes the cross-layer `AppEvent` contract (~200
  lines) with ~900 lines of UI modal state machines — split flagged.
- `app/mod.rs` regrew 990→1309: server/update/model-cache wiring + new
  handle_event arms; fix is per-domain arm delegation, not a new file.
- Semantic layer violates its own degrade-don't-crash invariant on lock
  poisoning (9+ bare `.lock().unwrap()`, embeds under lock in 3 paths).
- Tick/redraw divergence: background streaming forces a full redraw every
  120 ms with an unchanged focused frame.
- Dead config: `UiConfig::{show_status_bar, show_line_numbers,
  max_message_length}` have zero consumers.
- Verified clean: layering (no tools→app imports beyond 3 mapped reaches),
  server reuses provider wire types, all 07-04 fixes held except the oauth
  http-client share (never done), command-helper adoption has no regressions.

**Metrics at audit time**: clippy 0, tests 434, fmt clean; 42.2k LOC/166

# Part 2 — same-day defect batch (all 7 items fixed)

Executed the audit's suggested batch 1 in verified increments (build+test
green after the A+B clusters, full `fmt` + `clippy -D warnings` + test gate
at the end): **436 passed** (+2 new tests), clippy 0, fmt clean.

1. **win_job for MCP stdio** — `win_job` re-exported (`pub(crate)`) from
   `tools/background/mod.rs` (same pattern as the `force_kill_pid`
   re-export); `StdioTransport::new` binds every stdio child via
   `assign_child_handle`. A force-close can no longer orphan MCP servers.
2. **`'d'` remove-server off the loop** — mirrors toggle/reconnect:
   `tokio::spawn` + `McpOperationDone`. Stale `selected` after the list
   shrinks is safe: render indexes via `visible_indices`, keys use `.get`.
3. **`tick_is_visual` unified** — the predicate now checks the *focused*
   conversation; the `Tick` arm calls the same method instead of its
   diverged 3-clause copy. Doc comment states the lockstep requirement.
4. **Sub-agent malformed-tool recovery** — `parse_tool_calls_with_errors` +
   the main loop's bounded retry; `MAX_MALFORMED_TOOL_RETRIES` hoisted from
   a fn-body const to a `pub(crate)` module const and
   `malformed_tool_feedback` made `pub(crate)` so both loops share them;
   exhausted retries return an explicit `Err`. `parse_tool_calls` demoted to
   `#[cfg(test)]` (clippy's dead-code lint caught its last production caller
   disappearing — the audit's own theme, live). New test:
   `malformed_tool_call_is_retried_not_swallowed`.
5. **Semantic poison tolerance** — new `lock_inner()` helper
   (`PoisonError::into_inner`) on every blocking-path lock (13 sites, incl.
   the multi-line one in `spawn_init`); bounded event-loop paths unchanged
   (poison = busy, degrade). New test:
   `poisoned_lock_recovers_instead_of_panicking`. NOTE: embedding still runs
   *under* the lock — that's a hold-time concern covered by the bounded
   degrade paths, deliberately deferred (fixing it means restructuring
   embedder ownership; structure batch).
6. **401 stats order** — `requests` counted before the auth gate so
   `errors > requests` is impossible.
7. **`/export`** writes through `util::atomic_write`.

BUGS.md: all 7 entries moved to RESOLVED. STATE.md focus updated. Remaining
from the audit: dedup batches (client trio next), structure batch, owner
decisions (ACP, ServerCapabilities, reasoning_content inbound,
goal-evaluator double embedding).

# Part 4 — dedup batch B: agent + server (same day)

Two clusters, tested separately; final gate fmt + clippy `-D warnings` +
tests: **437 passed**, clippy 0.

**Agent (runner ↔ sub_agent residual):** the three shapes still duplicated
after 2026-07-04's `collect_stream` extraction now live once in runner.rs
(same precedent as batch 1's shared retry machinery):
- `dispatch_generic_tool(tools, mcp, name, args) -> (content, is_error)` —
  short-lock MCP client resolve + registry fallback; the sub-agent drops
  the flag and reports errors as plain result text (unchanged behavior);
- `build_step_request` — system prompt + running history →
  `CompletionRequest`;
- `tool_skip_message` — the per-step-limit tool_result text.
sub_agent.rs's tool dispatch is now a one-line delegate.

**Server (`server/openai.rs`):** chat and legacy streaming collapsed onto
`drive_sse_bridge` — one owner of the chunk channel + upstream spawn, the
reasoning-splitter pump, client-hang-up abort, the (previously duplicated
3-arm) upstream post-mortem, `data: [DONE]`, and the per-request session
discard. Dialects contribute three frame-shaping closures (`delta_frame`,
`tail_frame`, `final_frame`); the core tracks `is_first` itself, which
sidesteps sharing mutable state between closures. Semantics preserved
exactly: chat flushes the splitter tail as one more delta even when the
upstream errored; legacy returns `None` from `tail_frame` and folds the
tail into its finish frame. `sse_stream_response` deduplicates the
channel/poll_fn/headers scaffolding; `run_blocking_completion` the
complete → discard-session → error-mapping half of both blocking paths.

**New behavior (closes an audit RELIABILITY finding):**
`UPSTREAM_IDLE_TIMEOUT` (120s) around the bridge's `chunk_rx.recv()` — the
bridges no longer rely on the unenforced convention that every provider
configures its own read timeout; a silently stalled upstream is aborted
and the client gets an in-stream error frame.

Remaining from the audit: batch 4 (structure), sweepables, owner
decisions.
