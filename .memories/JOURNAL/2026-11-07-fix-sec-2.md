  человеком возвращалось. Стало: метка `.migrated-from-legacy` хранит `started_ms` и список сессий, которые видел
  перенос. Дополнение (`migrate::top_up_sessions`) копирует только сессии, которых перенос не видел, новее метки и
  которых нет в новой папке; настройки (whitelist, mcp.json, history, skills, чекпоинты) не дополняются; метка без
  списка не дополняет ничего. На каждом запуске один `stat` каталога `sessions` старой папки
  (`sessions_dir_changed`), обход — в фоновом потоке под тем же замком (5 с ожидания, иначе подберёт следующий запуск).
  Заметки о дополнении нет (прежняя «Data moved… delete it» для слияния была неверна — находка 9). Тесты:
  `a_new_session_of_the_old_binary_comes_but_a_deleted_one_never_returns`, `…only_when_its_sessions_directory_changed`,
  `a_marker_without_the_session_list_tops_up_nothing`; подмена (убрана проверка «виденного») роняет первый.
- **Находка 4 (Origin).** Решение ведущего: с ключом `Origin` не смотрим (`vscode-webview://`, `chrome-extension://`,
  `file://`, `null` работают, без bearer — 401, предзапрос OPTIONS проходит); без ключа — только loopback сервера и
  `allowed_hosts`, иначе 403 «set [server] api_key to allow this client». JSON для POST и `Host` остались, CORS-заголовки
  только при ключе, `*`. Тесты `with_a_key_any_origin_works_…`, `without_a_key_a_foreign_origin_is_refused_with_a_hint`,
  `cors_never_exposes_…` переписан. Документ обновлён.
