# 2026-11-06 — GW-SERVE: `/serve`, прокси и ACP работают через шлюз

Контракты: `.docs/gateway-contracts.md`, предыдущие шаги: `2026-11-06-gw-engine.md`, `2026-11-06-secrets.md`.
При `[gateway] enabled = false` всё прежнее: каталог по `[[providers]]`, поток сразу 200, без заголовков маршрута.
Закреплено тестом `with_the_gateway_off_the_old_path_is_unchanged` и всеми старыми тестами `server::*`.

## Сделано

- **`src/server/routing.rs`** (новый): `GatewayCell` (живой шлюз сервера, `RwLock<GatewayHandle>`), каталог по снимку
  (`model_ids`, `check_address`), заголовки (`route_headers`), тело статуса (`status_body`), `is_starting`.
- **Запрос через шлюз.** `openai.rs::resolve_backend` при включённом шлюзе: `check_address` → `provider_for_model_id(…, CallSource::Serve)`.
  Шлюз читается на каждом запросе (`context.gateway.get()`), поэтому правки конфига и пересборка (`/wipe`, готовность после старта)
  видны без перезапуска сервера. Приложение подменяет шлюз сервера через `App::sync_server_gateway` (две точки в `app/mod.rs`).
- **Каталог `/v1/models`.** `auto/<route>` (если в маршруте есть отдаваемый шаг) и `<account>/<model>` (модель по умолчанию, избранные,
  найденные у апстрима, режимы DeepSeek). Не показываются и не принимаются: подписки CLI (все три вида), выключенные и недоступные аккаунты.
  Неизвестный аккаунт, маршрут, модель или грязный адрес (пробелы, `..`, `?`, управляющие) — 404 `model_not_found`, апстрим не трогается.
  Голое имя модели или аккаунта за шлюзом не принимается (в каталоге его нет).
- **Fallback до первого байта.** Стрим через шлюз не отвечает клиенту, пока апстрим не дал первый чанк с текстом, вызовом или концом
  (`held_stream_completion`, `await_first`). Отказ до него — настоящий HTTP-код (429 + `Retry-After`, 502, 504…), после перехода на
  запасной аккаунт заголовки называют того, кто отвечает. После первого байта — ошибка кадром в потоке, второй аккаунт не подмешивается.
  Ответ с инструментами и `stream: true` через шлюз копится целиком и уходит одним ответом (иначе статус и заголовки неизвестны).
- **Заголовки**: `x-pooprusteek-account`, `-model`, `-route`, `-fallback` (аккаунты, отказавшие раньше, через запятую),
  `-fallback-reason` (коды классов). Значения только из видимого ASCII, длина ≤ 200; адресов и ключей в них нет.
  Берутся из `LLMProvider::served_by()` (новый метод с умолчанием `None`).
- **Статус** `GET /v1/pooprusteek/status` (и без `/v1`): за тем же bearer-ключом. С ключом сервера — аккаунты, состояния, лимиты
  (источник и возраст), последние решения, замечания конфига; тексты причин проходят `scrub` (URL → `<url>`). Без ключа сервера —
  урезанный вид (имена и состояния) и только при привязке к loopback; на сетевом адресе без ключа — 403. Без шлюза — 404.
- **CORS.** Ничего не менялось: `Access-Control-Expose-Headers` не ставится, поэтому `x-pooprusteek-*` чужой сайт прочитать не может;
  без ключа сервера CORS нет вовсе. Закреплено тестом.
- **Расход.** `stream_options.include_usage` разбирается из тела; насос теперь читает канал до чанка расхода OpenAI (ждёт до 3 с после
  `finish_reason`, и только если клиент просил) и отдаёт его последним кадром перед `[DONE]`, как у OpenAI (пустой `choices`).
  Ровно один раз в ledger — через `RoutedProvider`: `CallReport` с настоящим расходом (дедуп по `request_id`+`attempt`).
- **Отключение клиента.** Насос слушает `body_tx.closed()`: уход клиента гасит апстрим сразу, а не при следующем кадре. В
  `RoutedProvider::run` добавлен `CancelGuard`: оборванный вызов даёт одну запись `Outcome::Cancelled` с оценкой расхода
  (`EmitTracker::emitted_chars`), `report_failure` не зовётся — cooldown не включается. Это заодно закрыло пункт «прерванный вызов
  не пишет запись в учёт» из журнала ENGINE (для чата тоже).
- **ACP и прокси.** `run_acp_server` берёт `gateway::handle::main_provider` с `PendingGateway` (сборка на `spawn_blocking`,
  запрос ждёт готовности). Теперь ACP работает и с активной записью `[[providers]]`, а не только с DeepSeek-токеном (так же, как
  приложение). `server/proxy.rs`: `app::start_gateway` (сделана `pub(crate)`), событие `GatewayBuilt` подключает сервер и кэш моделей,
  переходы на запасной аккаунт попадают в журнал запросов, заметки загрузки конфига (в том числе «проектный конфиг ждёт
  `pooprusteek trust`») выводятся при старте.
- **Безопасность.** Клиент не задаёт `base_url`, ключи, заголовки аккаунта и опции CLI (лишние поля тела игнорируются, его
  `Authorization` апстриму не уходит — тест `a_client_cannot_steer_the_upstream_address_or_credentials`). Текст отказа авторизации
  апстрима и ключ в клиент не попадают (`upstream_auth_errors_and_keys_never_reach_the_client`). `/health` за шлюзом не перечисляет
  модели. `/embeddings` и `/rerank` при включённом шлюзе — 501 (они ходили мимо шлюза с ключами старых записей).
  Недоверенный проектный конфиг заблокирован на уровне `Config` (SECRETS): `--proxy` грузит конфиг той же `load_from_optional`.

## Изменения вне границ дорожки (минимум)

- `gateway/engine.rs`: `NotForServe` и отказ `provider_for_model_id` теперь для любого `cli:*`, а не только `cli:claude` (две строки).
- `gateway/routed.rs`: `served` + `publish_served`, `CancelGuard`, `LLMProvider::served_by`. `gateway/backend.rs`: `EmitTracker::emitted_chars`.
  `gateway/handle.rs`: `ServedBy`. `provider/mod.rs`: `LLMProvider::served_by` (умолчание `None`).
- `app/mod.rs`: `start_gateway` → `pub(crate)`, два вызова `sync_server_gateway`. `app/serve.rs`: шлюз в настройки сервера, каталог в
  `/serve`. `main.rs`: только `run_acp_server` (и удалён лишний `use std::sync::Arc`).

## Решения ведущего (в задании не было)

- Модель за шлюзом строго из каталога (`account/model`): неперечисленная модель — 404, а не проброс. Старый `/serve` пробрасывал любую; здесь
  каталог — единственный источник того, что можно использовать. Цена: аккаунт, которого нет в `[[providers]]` (кэш моделей ключуется записями),
  отдаёт только модель по умолчанию и избранные, пока кэш моделей не научится обновлять аккаунты шлюза.
- Ответ с инструментами через шлюз при `stream: true` не делится на дельты: копится и уходит одним ответом (было и раньше буферизовано).
- Для стрима без `include_usage` расход клиенту не шлётся; при просьбе, но без расхода от апстрима (DeepSeek-web) кадра расхода нет —
  оценку клиенту не выдаём (в ledger она есть с пометкой).

## Диалект Anthropic (`/v1/messages`) — отдельный этап, не начат

`ServerApi::Anthropic` по-прежнему отвечает 501, `/serve api anthropic` отказывает (`is_implemented`). Что потребуется:
1. Вход: разбор `messages` с блоками `text`/`image`/`tool_use`/`tool_result`, `system` строкой или блоками, `max_tokens` обязателен,
   `stop_sequences`, `thinking`; перевод в `CompletionRequest` (инструменты через `ToolBridge`, как в OpenAI-диалекте).
2. Авторизация: клиенты Anthropic шлют `x-api-key` и `anthropic-version`, а не `Authorization: Bearer`; нужен приём обоих ключей в `http.rs`.
3. Ответ: `message` с `content`-блоками, `stop_reason` (`end_turn`/`max_tokens`/`tool_use`), `usage.input_tokens/output_tokens`; поток событий
   `message_start`, `content_block_start/delta/stop`, `message_delta`, `message_stop`. Насос `drive_sse_bridge` уже принимает кадры закрытиями,
   удержание до первого чанка (`await_first`), расход и отключение клиента переиспользуются как есть.
4. Ошибки: конверт `{"type":"error","error":{"type":…,"message":…}}`, соответствие классов (`overloaded_error`, `rate_limit_error`,
   `authentication_error`, `invalid_request_error`, `not_found_error`), `Retry-After`.
5. Заголовки `x-pooprusteek-*`, каталог и проверка адреса — без изменений; `GET /v1/models` в формате Anthropic (`data[].id`, `type: "model"`);
   по желанию `POST /v1/messages/count_tokens` (оценка).
6. Тесты: тот же набор, что в `gateway_tests.rs`, плюс разбор инструментов и потока событий.
