## keys.rs decomposition (`app/keys/`) + file-size rule in CONVENTIONS

Closed the long-planned "keys.rs key→intent / intent→effect" item
(STATE.md CURRENT FOCUS since 2026-07-02). The 1318-line `app/keys.rs` is
now `app/keys/`, split by **input surface**, not by line count:

| Module | Lines | Owns |
|---|---|---|
| `mod.rs` | ~80 | `handle_key` — pure surface dispatch (onboarding → autocomplete-nav → modal → MCP view → chat) + `apply_text_key` |
| `chat.rs` | ~300 | chat-view keys + `submit_input` (backslash continuation, goal-mode interception, command vs message routing) — `SubmitOutcome::{Continue,Consumed,Quit}` preserves the original early-return-vs-refresh-autocomplete semantics exactly |
| `dispatch.rs` | ~160 | `apply_command_result` — the `CommandResult`→effects interpreter. `CommandResult` *is* the command intent enum; the interpreter was previously buried inside the Enter arm |
| `modal.rs` | ~300 | modal keys; NEW pure decoders `approval_key`/`confirm_key` (+ unit tests) following the existing `events::handle_picker_key` pattern; picker-selection effects extracted to `apply_picker_selection` |
| `mcp.rs` | ~365 | MCP view / auth picker / `/mcp add` steps + `spawn_mcp_add` |
| `onboarding.rs` | ~70 | token entry / model toggle / provider hot-create |
| `autocomplete.rs` | ~220 | nav interception, refresh (command+file modes), accept |

Wins beyond the split:
- **Per-keystroke `Modal` clone removed** — `handle_modal_key` now
  `take()`s the modal and moves it back when it stays open (audit MED
  finding; tool-approval `arguments` can be a large string). Verified all
  arms reassign-or-clear exactly as the clone-based code did, including
  `handle_mcp_add_key` (every path writes `state.modal` before returning).
- **Visibility tightened**: `handle_key` is the only `pub(crate)` item —
  everything else (`handle_mcp_key`, `refresh_autocomplete`,
  `accept_autocomplete`, `spawn_mcp_add`, …) dropped from `pub(crate)` to
  module-private/`pub(super)`; the event loop is the single entry point.
- Dead no-op `clamp_mcp_scroll` stub deleted (comment said "we manage
  scroll in the renderer"); identical Tab/Down and BackTab/Up autocomplete
  arms merged.
- `push_system` adopted in the moved code where byte-equivalent.

Also codified the **file-size rule** in `CONVENTIONS.md` (MODULE /
DECOMPOSITION PATTERN section): ~500+ non-test lines is a *trigger for the
"more than one reason to change?" question*, never an automatic split;
inline tests don't count against a file; hard smells are >150-line
functions and layer-mixing, not raw length. Context: owner asked whether
">400 lines is really bad" — answer recorded there so future agents don't
re-litigate it. (Raw `wc -l` misleads here: pre-split `events.rs` was 1194
lines but only ~320 of code — the rest is tests.)

Numbers: tests 265 → **267** (two new decoder test fns), clippy **0**,
build 0 warnings. All `app/keys/` modules < 400 lines.
