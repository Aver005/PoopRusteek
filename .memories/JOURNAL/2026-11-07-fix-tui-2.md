## Находка 1 (+11) — включение шлюза не теряет ключ и откатывается

Корень: в памяти `entry.api_key` — уже значение (ссылка развёрнута при загрузке), а `enable_gateway` подставлял
аккаунту `keyring:global/<имя>`. Теперь включение целиком идёт вне цикла событий (`enable_blocking`):
1. `config::raw_api_keys_at` читает ключи записей так, как они лежат в файле;
2. ссылка `env:`/`file:`/`cmd:`/любой `keyring:` переносится в аккаунт как есть (`secret = <та же ссылка>`);
   значение, лежащее в файле, идёт в хранилище под `account_secret_id(имя)` проверенным путём (`set_verified`);
   уже лежащее под этим именем (стартовый перенос) переиспользуется;
3. аккаунты собираются и проверяются (`validate`), конфиг пишется синхронно (`config::save_sync`);
4. любой сбой откатывает всё: положенные ради включения ключи удаляются, память не менялась, файл цел,
   шлюз выключен, `[[providers]]` на месте, сообщение «The gateway was not turned on: … Nothing was changed».
Память применяется только на событии `GatewayEnabled(Ok)`. Это же закрывает находку 11 (память и диск не расходятся).

Выключение: клавиша `X` на экране `/accounts` и `/accounts disable` — с вопросом `y/n`. Аккаунты и маршруты остаются
в файле; `[gateway] enabled = false` пишется синхронно, при сбое шлюз остаётся включённым. После: шлюз
пересобирается выключенным (`/serve` переходит на него), закрепления гаснут с заметкой, открытые чаты возвращаются
на провайдер из `[[providers]]`.

## Находка 3 — TUI из инструмента агента: ограниченный режим

`GatewayView::human_only()` = тестовый флаг или `secrets::human::is_agent_child()` (общая проверка, модуль не правил).
В ограниченном режиме: диалог доверия показывает причину и не даёт выбрать «Trust» (и `resolve_trust` сам отказывает,
даже при подделанном выборе); `/secrets set|rm|bind` — ошибка с объяснением (`commands/defs/secrets.rs`);
мастер не принимает ключ; `g` и `/accounts enable` не включают шлюз. Текст: «This screen was started from an agent
tool … Run pooprusteek in your own terminal.». Выключение шлюза и чтение (`/secrets list|test`) остаются.
Для документа (`.docs/secrets-and-config.md`, правит другой агент): «ребёнок инструмента агента» теперь ограничен и в
TUI, не только в CLI; сброс переменной по-прежнему обходит это смягчение — и это сказано в документе честно.

## Minor

- **7. MCP после согласия.** Выбрана небольшая правка: после «Trust» на файле MCP и перезагрузки конфига
  вызывается тот же `mcp::manager::reload`, что у `/mcp reload` (серверы проекта поднимаются без перезапуска, в чат
  идёт заметка). Наблюдение за самими файлами MCP и внешним `pooprusteek trust` не добавлено (нужен общий слежок за
  файлами; отдельная задача).
- **8. Несколько файлов.** `denied` — множество хэшей; диалог берёт первый запрос из `pending_trust_requests()`, чей
  хэш не отклонён, и после ответа сразу спрашивает следующий.
- **12. `End` и узкое окно.** «Прочитано» теперь значит «каждая строка хоть раз была на экране» (порядок обхода не
  важен), поэтому `End` не ловушка; `trust_view.max_room` без выдуманного минимума, при нулевом окне прочитать нельзя.
- **13. Онбординг.** Пока `View::Onboarding`, диалог не открывается; тик открывает его после.
