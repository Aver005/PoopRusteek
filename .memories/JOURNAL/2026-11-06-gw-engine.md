# 2026-11-06 — GW-ENGINE: движок маршрутизации шлюза

Контракты: `.docs/gateway-contracts.md`, предыдущий шаг: `2026-11-06-gw-0.md`. Ветка `t3/4498633a`.
Шлюз по-прежнему выключен (`[gateway] enabled = false`): `build_gateway` для выключенного отдаёт `DisabledGateway`,
`main_provider` идёт старым путём `build_provider`. Тест `a_disabled_gateway_builds_exactly_the_provider_the_old_path_builds`.

## Сделано

**Файлы дорожки** (`src/gateway/`):
- `engine.rs` — `Engine` (фасад `Gateway`), `Core::select` (одна функция выбора над конфигом, состоянием и часами),
  правки `apply_edit` с проверкой `validate()`, события, снимок, заглушка секретов `EnvOnlyResolver`, фабрики адаптеров
  (`BackendFactory`, `BuiltinFactory`), `EngineDeps`, `build_gateway`, `gateway_config(&Config)` (заглушка для SECRETS).
- `routed.rs` — `RoutedProvider`: fallback только пока `EmitTracker::emitted() == false`, место на аккаунте (семафор),
  `Backend::fork()` на смене цели, `flatten_for_switch` (с запоминанием длины развёрнутой части),
  `route_state`/`seed_route_state` (смена цели серверных сессий не удаляет, см. «Исправления по ревью»), серверные сессии DeepSeek через адаптер.
- `state.rs` — состояние аккаунта (`AccountState`), политика cooldown, `RouteState`, `HintStore` (`state.json`).
- `ledger.rs` — учёт по `(день, аккаунт, модель, источник)`, дедуп по `(request_id, attempt, аккаунт)`, сброс через
  `atomic_write` раз в 30 с фоновой задачей движка (`spawn_blocking`) и при выходе.
- `api_backend.rs` — `ApiBackend` поверх `build_entry_provider` (клиент на модель, лимиты общие), общий `drive_provider`
  (дочитывает поток до конца ради чанка расхода OpenAI). `deepseek_backend.rs` — `DeepseekBackend` (расход — оценка).
- `clock.rs` — `Clock`, `SystemClock`, `ManualClock` (только тесты). `testkit.rs`, `engine_tests.rs`, `routed_tests.rs` — тесты.

**Вне файлов дорожки, минимально:** `provider/model_cache.rs` (список моделей через живой `Backend::list_models`,
`set_gateway`), `session.rs` (`route_state`, `SessionMeta.route`, запись не затирает известную цель), `harness/mock.rs`
(скрипты на аккаунт, `retry_after`), `app/{mod,events}.rs` (поле `gateway`, `AppEvent::Gateway`, статус-строка при
`FallbackTaken`), `app/keys/onboarding.rs`, `harness/driver.rs` — все точки сборки на `main_provider`, кроме ACP и
`server/proxy.rs` (GW-SERVE).

## Решения по ходу (в контрактах этого не было)

- **Cooldown.** `Retry-After` — до секунды (потолок 24 ч). Без него 5 с → 5 мин ×2 с разбросом ±20 % (хеш, без `rand`).
  Квота без известного сброса и далёкий сброс → проба через 30 мин; `SpendCap` → 1 ч. `Overloaded/Timeout/Server/Network`
  тоже дают короткий cooldown (без него упавший аккаунт долбился бы на каждый вызов). Успех снимает любой запрет.
- **Возврат без человека (new-api #3537).** `Auth` → снова на пробу через 10 мин, `AccountBlocked` → через 1 ч
  (`AccountState::recheck_at`; статус в интерфейсе остаётся `NeedsAttention` до срока). Выключенное человеком не возвращается.
- **После перезапуска (CLIProxyAPI #5404).** Пишутся только подсказки `Exhausted` (`state.json`). Подсказка с будущим
  сроком ставит аккаунт в конец порядка (в решении виден как `Exhausted{resets_at}`), но не блокирует: единственный
  аккаунт вызывается, первый вызов решает, успех стирает подсказку. Битый файл игнорируется.
- **Порог «заранее».** `soft_pct`/`switch_at_pct` только по `is_hard_signal` (заголовки или событие CLI, возраст ≤ 120 с);
  `hard_pct` убирает аккаунт совсем (`SkipReason::OverHardLimit`). Снимки `Ledger`/`Declared` и старые не решают.
  Оценка по заявленному `requests_per_minute` показывается в `AccountView.limits` с источником `Ledger`.
  «Подождать вместо сжечь» (A-03) не сделано; место — `Decision::retry_at`.
- **Fallback.** Помимо `route.on`, всегда разрешены `ContextTooLong` и `ModelNotFound` (таблица §3.7). Закреплённый
  аккаунт и `account/model` без запасных не переходят. Пустой поток без `finish_reason` — отказ класса `Server`
  (иначе ход «успешно» кончался пустотой). Когда выбирать некого: была настоящая ошибка — отдаётся она (класс сохранён,
  `retry_after` подправлен по ближайшему возврату); не было — `RateLimit{retry_after}` либо `Overloaded` с `explain()`.
- **Смена цели.** Развёрнутая часть истории помнится (`flatten_prefix`) и разворачивается снова на каждом вызове, иначе
  старые id и подписи вернулись бы со второго вызова. Смена модели у того же аккаунта тоже считается сменой (подписи Gemini).
  Нет ни привязки, ни `route_state` — историю не трогаем (как до шлюза).
- **Токены в учёте.** Расход берётся из `CallReport` (последнее слово сервера), а не суммой чанков: чанк расхода OpenAI
  приходит один раз, повтор записи гасится дедупом.
- **Харнесс.** Пока `[gateway]` не встроен в `Config`, `harness/driver.rs` читает настройки шлюза из файла,
  названного в `POOPRUSTEEK_GATEWAY_TOML`, и только вместе с `--config` (без него переменная игнорируется).
  Файл проверяется `validate()`: ошибки — отказ до первого хода. TODO(SECRETS): убрать, когда `[gateway]` будет в `Config`.
- **Трасса.** `debug_log` из слоя шлюза: `gateway.decision` (explain, цель), `gateway.fallback`. В цикл агента ничего не добавлено.

## Изменения контрактов (кого касается)

- `handle.rs`: `SkipReason::{OverHardLimit, NotForServe}`, `Gateway::backend_for` (по умолчанию `None`). → GW-TUI, GW-SERVE.
- `backend.rs`: у `Backend` добавлены методы с умолчаниями: `accepts_attachment`, `context_window`,
  `list_remote_sessions`, `delete_remote_session_by_id`, `fetch_remote_session_messages`, `check_session`, `adopt_session`
  (их реализует только адаптер с `server_side_session`; без них шлюз с DeepSeek потерял бы `/delete`, `/load`, вложения). → GW-CLI (ничего делать не нужно).
- `provider/mod.rs`: `LLMProvider::{route_state, seed_route_state}` (умолчания `None`/пусто); снят `expect(dead_code)` с
  `usage` и `rate_limits`. `failure.rs`: `Cancelled` оставлен под `expect` (его создаст GW-SERVE).
- **`BackendFactory`** (`engine.rs`): движок спрашивает фабрики по порядку, первая взявшая аккаунт побеждает.
  **GW-CLI** пишет свою для `cli:*` и добавляет её в `EngineDeps::for_config` (сейчас там только `BuiltinFactory`).
- **`SecretResolver`/`Secret`/`SecretError`** — заглушка в `engine.rs` (форма как в контракте). **SECRETS** при слиянии
  заменяет определения на `crate::secrets::*` и подставляет настоящий резолвер в `EngineDeps::for_config`.
- **`gateway_config(&Config)`** возвращает выключенный шлюз. **SECRETS** меняет тело на чтение `Config.gateway/accounts/routes/roles`.
- **`ConfigPersist`** (`engine.rs`): куда сохранять `apply_edit`. Без него правки живут до перезапуска. **SECRETS** реализует через слои.
- `session.rs`: `Session.route_state`, `SessionMeta.route`. Литералы `Session` в `app/sessions.rs`, `commands/defs/import.rs`,
  `tui/capture.rs` получили `route_state: None` (по строке; `tui/capture.rs` — файл GW-TUI, правка одной строки).
  `PersistJob::SaveSession.meta` теперь `Box<SessionMeta>` (clippy `large_enum_variant`).
- `harness/mock.rs`: `[[reply]] account = "a"`, `retry_after = 30`; путь `/a/v1/…` выбирает скрипт аккаунта, у каждого свой курсор.

## Не сделано / открыто

- ACP и `server/proxy.rs` — GW-SERVE. `/pin` — `DecisionQuery.pinned` в `decide()` работает, у `RoutedProvider` пока нет
  публичного закрепления (адрес `account/model` даёт `Fixed`).
- Аккаунт, у которого не собрался адаптер (нет переменной окружения), остаётся `Unavailable` до правки конфига или перезапуска:
  автопересборки нет. Пометки «модель недоступна у аккаунта» (`ModelNotFound`) нет — защищает только `failed` вызова.
- Прерванный вызов (ход отменён) не пишет запись в учёт и не удаляет серверную сессию свежего форка.
- После ухода с DeepSeek на другой аккаунт и обратно DeepSeek получает свежую сессию (локальная история ей отправляется
  целиком), а оставленная серверная сессия остаётся в аккаунте. Сохранённая ссылка на неё жива, но `/load` по ней
  подхватит ветку без реплик, которые шли на другом аккаунте: приемлемая цена (так же устроена ступень 2 контекста),
  улучшение — сверять `Session.route_state` с владельцем ссылки при загрузке.
- `limits.json` (снимки лимитов между запусками) не пишется: после перезапуска они всё равно были бы устаревшими.
- `cost_usd` пуст (нет проверенного источника цен), `budget_usd_month` не применяется.
- Живой прогон с настоящим DeepSeek-токеном и CLI не делался (нет права использовать токены).

## Ошибки и уроки

- Фикстура потока OpenAI без полей `id/object/created/model` молча разбиралась как пустой поток: тест упал «stream ended
  without a reply». Хорошо, что пустой поток теперь отказ, а не успех; фикстуры брать из `compat_http_tests.rs`.
- `cargo clippy --tests` ловит старые замечания в тестах других модулей; хук гоняет `cargo clippy --bin pooprusteek`, ровно им и проверять.

## Исправления по ревью (`.dev/research/review-gw-engine.md`)

Ветка влита с `feature/gateway-release` (зависимости, `tokio` без `full`): конфликтов нет, сборка и 1476 тестов зелёные.

**F2 (critical) — смена цели не удаляет серверную сессию.** Из `RoutedProvider::commit` убран `discard_in_background`:
прежний адаптер просто отпускается, подхваченная `adopt_session` сессия (из `/load`, `--resume`) не затрагивается
ни fallback-ом, ни мягким порогом, ни правкой конфига. Ссылка в файле сессии не стирается: после ухода на API-аккаунт
`session_identity()` даёт `None`, а `RemoteLink::Unknown` оставляет прежнее. Удаляется только сессия свежего форка
упавшей попытки, и только если она не дала ни текста, ни вызова (`!error.emitted`). Тесты: `a_session_adopted_by_load_survives_a_fallback_and_a_config_edit`,
`moving_to_another_account_never_deletes_the_session_the_user_sees`, `the_users_own_discard_and_delete_still_reach_the_server`
(пользовательские `discard` и `/delete` доходят), `a_failed_attempts_own_session_is_discarded_only_if_nothing_was_shown`.
Старый тест `leaving_a_server_session_discards_it…` закреплял удаление и заменён.

**F1 — чужие вызовы не уходят другому аккаунту.** Три слоя: (а) `reset()` больше не стирает происхождение истории, а
превращает привязку в подсказку (`seed`); `route_state()` отдаёт привязку, а без неё подсказку; (б) `switch_provider`
переносит `route_state` прежнего провайдера в новый; (в) страховка: нет ни привязки, ни подсказки, а история несёт
вызовы с id или `provider_state` — разворачивается вся (свежий провайдер не мог их породить). Сквозные тесты:
`app::sessions::tests::a_loaded_session_never_hands_foreign_calls_to_another_account` (настоящий `handle_load_session`
с `App::new`), `harness::driver::tests::a_resumed_session_keeps_its_origin_…` (настоящий `adopt_remote_session`),
`app::tests::switching_provider_hands_the_route_origin_to_the_new_one`; у каждого обратная сторона «история с того же
аккаунта остаётся родной» (она ловит потерю подсказки при `reset`: проверено подменой кода — тесты падают).
Промпт DeepSeek: после разворота вызов с аргументами лежит в тексте ассистента, результат не остаётся без вызова
(`a_switch_turns_foreign_tool_calls…` строит настоящий `build_prompt`).

**F3 — параллельные процессы не затирают учёт.** `EngineLedger` держит `rows` (вид) и `pending` (дельта с последнего
сброса); `flush` читает файл, прибавляет дельту, пишет через `atomic_write` и берёт слитое как новый вид; при ошибке записи
дельта возвращается. `state.json`: `HintStore::merge_save` — по аккаунту побеждает более поздний `saved_at`, снятые у нас
подсказки (`cleared_hints`: успех, включение руками) стираются, только если на диске они не новее; истёкшие отбрасываются.
Запись по-прежнему в `spawn_blocking` раз в 30 с и при выходе. Остаётся маленькая гонка между чтением и `atomic_write`
(допустимо по решению ведущего); замков нет. Тесты: `two_processes_flushing_the_same_file_add_up_instead_of_overwriting`,
`a_second_flush_adds_only_what_is_new`, `a_failed_write_keeps_the_pending_counts…`, `saving_hints_keeps_what_another_process_wrote`,
`a_cleared_hint_goes_away_unless_the_disk_copy_is_newer`.

**F4 — `validate()` при сборке.** `Engine::new` проверяет конфиг и раскладывает ошибки (`Issues`): аккаунт с ошибкой —
`Unavailable{причина}` и `SkipReason::InvalidConfig`, маршрут или роль с ошибкой не используются
(`provider_for_role` → `None`, приложение остаётся на старом пути; `decide()` → `Why::ConfigInvalid`, `explain()` «route is off: …»).
`GatewaySnapshot.problems` несёт замечания; `App::new` пишет в статус-строку, сколько ошибок и первую (приложение запускается).
`apply_edit` отказывает только по новым ошибкам: чинить сломанный конфиг по одной правке можно. Смесь инструментов без
`allow_mixed_tools` больше не превращается в промптовый режим. `max_concurrency = 0` — ошибка конфига, семафор не меньше 1.
`BuiltinFactory` отказывает `direct_token` для Claude (провайдер или хост) и без `direct_token_ack` независимо от `validate`.
Харнесс валидирует файл и отказывает до первого хода. Контракт: `GatewaySnapshot.problems`, `SkipReason::{InvalidConfig,
NoAttachmentSupport}`, `Why::ConfigInvalid` — аддитивно (GW-TUI показывает, GW-SERVE не затронут); `types::is_claude_host`
стал `pub(crate)`; `validate` требует модель у шага API-аккаунта (см. m4).

**F5 — вложения не теряются.** `accepts_attachment` отвечает по цели, куда файл реально уйдёт (`select` с файлами). На вызове
файлы хвоста после последней реплики модели ограничивают выбор аккаунтами, которые их приложат (`NoAttachmentSupport`);
если таких нет, ход кончается ошибкой «the attached file (…) was not sent» (класс `RateLimit` с ожиданием, если приложить
мог бы остывающий аккаунт, иначе `BadRequest`), на аккаунт без файлов ход не уходит. Файлы прошлых ходов цель не фиксируют.
Тесты на обе стороны: `a_file_goes_to_the_account_that_can_attach_it…`, `when_nobody_can_take_the_file…`, `a_file_from_an_earlier_turn…`.

**Minor.** m1: `Retry-After: 0` считается отсутствующим, берётся backoff. m2: строка `state.json` с переполняющим временем
пропускается (`checked_from_unix`), запуск не падает. m4: у API-шага без модели ни на шаге, ни на аккаунте — ошибка
конфига (`validate`), на вызове — `InvalidConfig`; DeepSeek с пустой моделью берёт `[provider].model` (раньше уходил в
Instant через `auto/main`). Пример `lmstudio` в тестах дополнен моделью. m5: `FallbackTaken` шлётся после захвата места, гонка его не съедает.
m6: `drive_provider` ждёт чанк расхода не дольше `USAGE_GRACE` = 2 с после `finish_reason` (меньше `AFTER_STOP_GRACE` = 5 с), вызов
засчитывается, `commit` не теряется (`a_stream_left_open_after_the_finish…`; расход тогда оценка с `~`). m8: `LimitsUpdated` —
только когда изменились сами окна, а не время наблюдения. m9: модульные заголовки и доккомментарии новых файлов — не больше двух строк.

**Остальное minor — отложено с причиной.**
- m3 (класс ошибки «ждите до» всегда `RateLimit`): нужен класс по причине ближайшего пропуска (Auth для `NeedsAttention`, Quota для `Exhausted`);
  потребителя пока нет (`/serve` в GW-SERVE, авто-ретрая нет), поэтому правка вместе с ним, не вслепую.
- m7 (`ConfigChanged` не пересобирает провайдера открытой беседы): `tool_mode` — константа провайдера по контракту; пересчёт на ходе
  меняет это соглашение и затрагивает сборку промпта в `app/mod.rs`; решить вместе с GW-TUI (экран правит маршруты и сам вызовет `rebuild_provider`).
