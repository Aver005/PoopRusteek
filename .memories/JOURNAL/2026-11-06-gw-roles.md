# 2026-11-06 — GW-ROLES: служебная модель, заголовки чатов, заполнение окна

Контракты: `.docs/gateway-contracts.md` (раздел GW-ROLES), идея I-09,
план: `.docs/research-2026-11/02-gateway-architecture.md` §3.9. Предыдущие шаги:
`2026-11-06-gw-engine.md`, `2026-11-06-gw-cli.md`. Ветка `t3/bec75b8a`.

Роль есть — служебный вызов идёт по её маршруту; роли нет (шлюз выключен или
маршрута в `[roles]` не осталось) — прежний путь, байт-в-байт.

## Сделано

**Заголовки чатов — `src/app/titles.rs` (новый).**
- `maybe_request_chat_title` зовётся из `on_agent_event` после законченного хода
  (`TurnEnd::Done`), ставит `Conversation.title_requested` и уходит в `tokio::spawn`:
  цикл событий сеть не ждёт (инвариант 1).
- `spawn_title_request` → `gateway.provider_for_role(Role::Title, CallSource::Role(Title))`,
  затем **форк** и `fetch_title`: `SessionDiscard` убирает серверную сессию форка,
  поэтому чатов в аккаунте DeepSeek не остаётся, а в историю беседы вызов не попадает.
- `TITLE_TIMEOUT` = 10 с; ошибка, пустой ответ, таймаут и ненастроенная роль — просто
  нет события: на экране ничего не меняется, `session::derive_title` остаётся запасным.
  Повтора нет: `title_requested` ставится до запроса.
- `clean_title` — текст модели недоверенный: первая непустая строка, без разметки,
  кавычек вокруг, управления и с подписей «Title:»/«Заголовок:», пробелы схлопнуты,
  хвостовая точка убрана, пустое не принимается. Обрезка — по символам (инвариант 4),
  `TITLE_MAX_CHARS` = 60.
- `title_prompt` даёт первой просьбе и первому ответу; язык заголовка задан системным
  промптом («in the language of the conversation»). Инструменты в запрос не идут никогда.
- Результат — событие `AppEvent::ChatTitle`: `on_chat_title` пишет `Conversation.title`
  и, если чат на экране и не стримит, ставит автосейв (пишет тот же воркер, что и ходы).

**`Session.title` (`src/session.rs`).** Поле `Option<String>` с `#[serde(default)]`,
старые файлы читаются. `SessionMeta.title`; `save_session` при `None` берёт заголовок
из файла (`stored_title`, как `stored_route`), поэтому автосейв его не затирает.
`list_sessions` показывает сохранённый заголовок, `derive_title` — запасной.
Литералы `Session` получили `title` (`app/sessions.rs`, `commands/defs/import.rs`,
`harness/driver.rs`, `tui/capture.rs` — по строке; `tui/capture.rs` — файл GW-TUI).
`handle_load_session` поднимает заголовок в чат и ставит `title_requested`.
`/chats` (`multichat::conversation_title`) показывает служебный заголовок, если он есть.

**`/compact` (`app/multichat.rs`).** `summariser_for`: роль `Summary` → её провайдер,
иначе `chat.fork()` как раньше. `context::compact` и проверка формы `summary::validate`
не тронуты; сброс серверной сессии остался на провайдере самого чата.

**Оценщик GOAL (`app/goal.rs`).** `evaluator_for`: роль `Evaluator` → её провайдер,
иначе форк провайдера чата; нет ни того, ни другого — цикл отменяется прежней строкой.

**`validate` (`gateway/types.rs`, аддитивно).** Явные роли `title`/`summary` не могут
указывать на маршрут с `cli:*` (`roles.Title: route 'coding' uses account 'claude-work'
(CliClaude), whose CLI starts cold (3-4 s): …`). Наследование от `main` не наказывается:
основной чат на CLI — обычное дело. Тестовый пример конфига и `config.example.toml`
получили дешёвый маршрут `cheap` на API-аккаунте (`gpt-5.5-mini`).

**Заполнение окна (`agent/runner.rs::context_used`).** Настоящий расход (`usage`,
он же `session_tokens`) верим только у провайдера, который сам ведёт историю; у
остальных на провод уходит локальная история, и меряется она прежней оценкой.
Отдельного доступа к `CallReport.usage` в `LLMProvider` нет — расширять трейт вне
дорожки не стал, поэтому для API-провайдеров осталась прежняя оценка.

**Вне файлов дорожки, минимально:** `app/events.rs` (`AppEvent::ChatTitle`),
`app/mod.rs` (`mod titles`, ветка диспетчера, вызов после законченного хода),
`app/conversation.rs` (`title_requested`), `app/sessions.rs` (заголовок в `SessionMeta`,
загрузка). Правки аддитивные, строк по одной.

## Проверено

- `cargo test --bin pooprusteek`: 1792 passed, 0 failed, 10 ignored. `cargo clippy --bin pooprusteek -- -D warnings`, `cargo fmt --check` — чисто.
- Обе стороны каждого пункта: заголовок есть при успехе (`a_clean_model_answer_becomes_the_title`),
  нет при отказе и таймауте (`an_empty_or_failed_answer_leaves_the_fallback`,
  `a_silent_service_model_times_out`), запасной остаётся, повтор не уходит
  (`a_chat_asks_for_a_title_once_and_only_when_the_role_is_set` — два вызова, один запрос).
  Очистка: разметка, перевод строки, кавычки, управляющие, подпись, многоточие — те же тесты;
  пустой ответ не принимается. Роль title ведёт вызов, `discard_session` вызван
  (`the_title_role_takes_the_call_and_cleans_up_its_session`).
- `/compact` и GOAL: без роли — провайдер чата (`model() == "fake"`), с ролью — служебный
  (`"auto/cheap"`) (`the_summary_role_takes_the_compaction_call_only_when_it_is_set`,
  `the_evaluator_role_takes_the_goal_call_only_when_it_is_set`).
- Заголовок на диске: старый файл без поля грузится, автосейв его не затирает,
  список предпочитает служебный заголовок (`a_title_loads_from_old_files_and_survives_an_unaware_save`,
  `the_session_list_prefers_the_service_title_over_the_fallback`).
- Подмена кода: `fetch_title` без `clean_title` валит `a_clean_model_answer_becomes_the_title`
  и `an_empty_or_failed_answer_leaves_the_fallback`; снятая проверка `title_requested`
  валит «один запрос на чат» (2 вызова вместо 1). Обе подмены откатаны.
- Живые подписки, настоящие токены и `.dev/harness-config.toml` не использовались:
  только `FakeProvider`, `gateway::testkit` и временный `--data-dir` не нужен —
  файлы сессий тесты пишут и сразу удаляют, как соседние тесты `session.rs`.

## Не сделано / открыто

- Заголовок пишется в файл только для чата на экране (как и вся история: автосейв
  идёт по фокусу). Параллельный чат сохранит заголовок со своим следующим автосейвом.
- `CallReport.usage` (реальный вход последнего вызова API) в `LLMProvider` не выведен:
  заполнение окна у API-аккаунтов осталось оценкой. Это правка трейта — вне дорожки.
- `[roles] title = "off"` из ранней записи не понадобился: роль без маршрута просто не
  вызывается, а `validate` отсекает медленные CLI-маршруты.
- Экран и подсказки TUI заголовок не показывают: там `src/tui/**`, дорожка GW-TUI.
