## Evening session: "stream ended early" on every turn (agent)

**Symptom:** every agent reply ended with the system warning "stream ended
early, but a complete tool call was recovered" and turns died mid-thought
(final text answers surfaced as `AgentError`; one step got an empty response
and silently ended the turn).

**Root cause:** the staged strict-stop work assumed DeepSeek terminates its
completion SSE with `data: [DONE]` and turned clean EOF into
`Err("stream ended before [DONE]")`. The live protocol never sends `[DONE]`
(0 occurrences across a 12-step `.dev/debug.log` session) — the server ends a
completed response by closing the connection. So every healthy step became a
provider error: mid-loop steps were "salvaged" (the constant warning), and
the final no-tool-call step aborted the turn as `AgentError`.

**Fix (provider layer only, runner untouched):**
1. `provider/deepseek/stream.rs` — `process_stream_line` now returns a
   `StreamEvent { text, parent_message_id, finished }` and recognizes explicit
   finish signals: `[DONE]` with or without a space after `data:`, status
   patches (`{"p":"response/status","v":"FINISHED"}`, bare `{"v":"FINISHED"}`),
   terminal `{"o":"BATCH","v":[...]}` containing a status patch, and full
   response objects with `status == "FINISHED"`. 8 new unit tests.
2. `provider/deepseek/mod.rs` — both `complete` and `complete_stream` treat
   clean EOF as a normal stop (chunked-encoding truncation surfaces as a read
   error on `stream.next()`, never as clean EOF, so this is safe); explicit
   finish events stop before EOF when the server does send them.
3. Observability: unrecognized SSE lines are now logged
   (`completion.{stream,collect}.skipped`) — previously only recognized lines
   were logged, so whatever the server sends between the last content chunk
   and EOF (~240ms gap) was invisible. Next session's log will show it.

**Still unexplained:** one step (12/256) returned only the metadata event and
closed with zero content — possibly rate limiting from 12 requests in ~30s or
content in an event shape we drop. The new skipped-line logging will reveal
which; a bounded runner-side retry for empty steps is the candidate fix if it
recurs.
