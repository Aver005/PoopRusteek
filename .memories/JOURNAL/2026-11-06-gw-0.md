# 2026-11-06 — GW-0: эксперимент с CLI, дыры провайдеров, контракты шлюза

Отчёт эксперимента: `.docs/research-2026-11/06-cli-spike.md`. Контракты по дорожкам: `.docs/gateway-contracts.md`.
Ветка `t3/cf404617`, три логических шага (коммиты в `git log`).

## Сделано

**Часть 1. CLI.** Claude Code 2.1.318 и OpenCode 2.2.5 работают как чистая модель при строгом наборе флагов,
доказано файлом-приманкой с контролем (без флагов файл создаётся). Codex не установлен; по исходникам
пользовательского выключателя всех инструментов нет → «не поддерживается в режиме модели».
Находки, которых не было в плане:
- `--tools ""` у Claude не останавливает **хуки** пользователя и проекта (хук выполнил команду): нужен `--restricted` (≥ 2.1.248) или `--safe-mode`.
- `opencode run` без `--standalone` идёт в фоновую службу пользователя и **игнорирует** `OPENCODE_CONFIG_CONTENT` и `XDG_DATA_HOME`: запрет инструментов не действует, файл создался.
- `opencode --standalone` читает глобальный конфиг (MCP, плагины); с упавшим MCP-сервером запуск молчал 25–60 с. Лечится пустым `XDG_CONFIG_HOME`.
- У Claude есть бесплатный источник лимитов подписки: событие `rate_limit_event` (`five_hour`, `seven_day`) и `contextWindow` в `result`; у OpenCode ни того ни другого.

**Часть 2. Провайдеры** (коммит `fix(provider)`).
- `AppError::Upstream(ProviderFailure)` с `FailureClass`, `Retry-After` (секунды, HTTP-дата, `retryDelay` Gemini), заголовками лимитов OpenAI и Anthropic; `LLMProvider::rate_limits()`.
- `/serve`: 429 остаётся 429 с `Retry-After`; квота — 429 `insufficient_quota` без заголовка; ошибка ключа апстрима — 502 (не 401, ключ не клиента); контекст — 400; перегрузка — 503. Путь с инструментами не теряет тип (`StreamOutcome.failure`).
- Расход в потоке: OpenAI `include_usage` (одна повторная отправка без параметра при 400/422, отказ запоминается на аккаунт и форки), Anthropic `message_start`+`message_delta`, Gemini `usageMetadata`; 200 без `usage` разбирается как «расхода нет».
- Тесты: настоящий HTTP на локальном сокете (429 с заголовком и без, квота, 200 без usage, поток с расходом и без, отказ `stream_options`, посторонний 400 не повторяется).

**Часть 3. Контракты** (коммит `feat(gateway)`): `types`, `backend`, `handle`, `history`; `mod gateway` в `main.rs` под `#[expect(dead_code)]`.

## Решения без вопроса владельцу

- Файлы вне списка границ, тронутые минимально: `provider/mod.rs` (`CompletionChunk.usage`, `Usage`, `rate_limits`), `provider/deepseek/mod.rs`, `provider/fake.rs`, `agent/stream.rs`, `agent/runner.rs` (тест), `server/openai.rs` — по одной строке `usage: None` и поле `failure`. Иначе `CompletionChunk` не расширить.
- Расход OpenAI идёт **отдельным чанком после `finish_reason`**, а не задерживает терминальный: иначе сервер, не закрывающий соединение, подвесил бы ход. Цена: читающий только до `finish_reason` (`collect_stream`) расхода не увидит; фасад обязан дочитывать поток (в контракте ENGINE).
- `Usage.prompt_tokens` теперь включает кэш Anthropic (раньше только `input_tokens`): у `/serve` без `cache_control` разницы нет.
- `SpendCap` по типу `billing_error` (документация), а не по отсутствию `Retry-After`. Вживую не проверено.
- `ChatCompletionResponse.usage` стал `Option` на входе: сервер без `usage` в 200 раньше ломал разбор.
- `Credential` собирается из плоских полей конфига; `FailureClass` один на провайдер и шлюз.
- В `[provider_models]`/`model_cache` ничего не менял: за ENGINE.

## Ошибки и уроки

- Сначала я пытался править файлы Python-скриптом по точному тексту; `rustfmt` ломал отступы вставок, и три правки молча не применялись (скрипт падал целиком на второй замене). Дальше: `Edit` для точечных правок, `cargo fmt` после массовых.
- `taskkill /T` на зависшем `opencode` завершил цепочку процессов; чужой фоновый сервис OpenCode (`serve --service`) не трогал.
- `toml::de::Error` печатает строку исходника со значением секрета: SECRETS обязан не выводить его целиком (в контрактах).

## Ревью (ведущий)

- M1: повтор без `stream_options` теперь на любой BadRequest, а отказ запоминается только если повтор помог.
- M2: тело 401/403 апстрима не уходит клиенту `/serve`.
- M3: прямой токен запрещён и по хосту Anthropic; `cli:claude` принимает только `home`.
- Остаётся: `openai`-провайдер с прокси на Anthropic и секретом на уровне конфига не распознать.
- Отложено для GW-ENGINE и SECRETS: семантика `total_tokens` у Gemini, `deny_unknown_fields` и проверка `schema`, `failure` читает только `/serve`, usage на обычных дельтах OpenAI.
