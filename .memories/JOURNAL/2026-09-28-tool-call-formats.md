# 2026-09-28 — вызовы инструментов во всех известных форматах

Заказчик: «чатовая версия DeepSeek постоянно ошибается в вызове инструментов,
агент почти непригоден». Предложение — поддержать все варианты оформления
вызова, вперемешку в одном ответе. План, факты, решения и отступления от
эталонов — `.docs/tool-call-formats.md`; справка — `reference/TOOLS.md`,
раздел TOOL-CALL PARSING.

## Что было измерено до работы

- `mine .dev --sessions`: 19 трасс, 32 сессии, 0 ошибок разбора. Данные — до
  обновления модели 24.09; сессий после 21.09 в `%APPDATA%\pooprusteek` нет.
  Незнакомый формат `mine` не видит вовсе: он считает только жалобы парсера.
- По коду: незнакомый формат → ноль вызовов и ноль ошибок → `finish_or_retry`
  отдаёт `StepEnd::Answer`. Ход молча кончается прозой до вызова (поток режется
  на первом `<`), модель о неудаче не узнаёт.
- Веб отдаёт формат DeepSeek **V4.1**: ` calls`/` invoke`/` parameter` с
  ведущим пробелом (sglang `deepseekv41_detector.py`, vLLM `<｜DSML｜ calls>`).
  «Искажённый DSML» журнала 2026-09-24 — это он; отличие — удвоенная черта.
- Дыры DSML против эталона: самозакрытый `invoke …/>` терялся, тело `invoke`
  JSON-ом давало `{}`.
- Эталоны: vLLM `ccfd1cea` — 47 парсеров, sglang `6aacca2d` — 37 детекторов.

## План и критика

Первая версия плана ушла трём критикам (код и архитектура; безопасность;
полнота форматов). Принятое, по весу:

- итоговый текст шага не доходил до экрана — лента собиралась из потока;
- ~30 новых разметок = исполнение цитат: введено доверие (наши и DeepSeek —
  как раньше, остальное — только через человека, без него — отказ), блок кода
  исполняется, только если в нём одни вызовы, эхо вывода инструмента — отказ;
- набор независимых регулярок ломался на вложенности → однопроходный сканер;
- закрывающий тег внутри значения резал файл → конец JSON разбором, закрытие
  значения — только перед тегом диалекта;
- перечень форматов исправлен (MiMo, dots, MiniMax M2/M3, Longcat, granite-20b,
  варианты DSML `toolcalls`/`tool`, три формы Mistral).

## Что сделано

Шаги 1–13 плана. Разбор — `agent/tool_parser/`: `scan.rs` (сканер), `accept.rs`
(приёмка, доверие, страховка), `catalog.rs` (имена и схемы на ход), `formats/`
(грамматики), `visible.rs` (поток). Цикл: заметка об ошибках рядом с вызовами,
сброс бюджета после шага с вызовами, повтор по страховке. Показ: итог шага
заменяет поток. Подтверждение: `ToolApprovalRequest::always_ask`. DeepSeek:
`ThinkRouter` прячет рассуждения в `<thinking>`.

Грамматики семейств 2–6 и слабых форматов написали пять агентов параллельно
по общему контракту, без cargo (параллельные сборки на этой машине падают по
памяти); регистрацию и сборку вёл один интегратор. Итог сборки: 2 ошибки
видимости, 7 падений на стыках семейств (процитированный маркер давал `Err`
вместо `None`, MiniCPM5 искал `</parameter>` вместо `</param>`, тест ждал, что
JSON в `<tool_call>` никто не возьмёт).

## Проверка

- Тесты 923 → 1113. Матрица смесей: 13 семейств, 156 упорядоченных пар с
  прозой между — оба вызова, в порядке текста.
- **Найдена и закрыта дыра:** чужой вызов незнакомого инструмента становился
  прозой, сканер шёл дальше с конца маркера — и доверенный `<tool_use>` в его
  аргументе выполнялся без подтверждения. Теперь отвергнутая находка — проза
  целиком. Проверено пробником: без правки тест
  `a_call_inside_a_rejected_foreign_call_never_runs` падает.
- **Замер ложных срабатываний** на тексте проекта (`src/app`, `src/tools`,
  `src/provider`, `src/mcp`, `.memories/JOURNAL`, `.docs`) с каталогом встроенных
  инструментов. Первый прогон — 5 файлов; два дефекта:
  - битый маркер во встроенном коде (`` `<tool_calls>[…]` ``) давал ошибку:
    правило «закрывающая кавычка внутри вызова» срабатывало на битой находке,
    тянущейся до конца текста — теперь учитываются только целые вызовы;
  - страховка срабатывала на таблице markdown `| task |` (ASCII-черта считалась
    концом спецтокена) — теперь нужен `｜` или `|>`.
  Второй прогон — 3 файла, все ожидаемые: два образца с заполнителями
  (`{JSON}`, `[TOOL:name] {...}` — старый разбор давал ту же ошибку) и цитата
  настоящего вызова в журнале 2026-09-24 (страховка, одна попытка).
- `cargo clippy --bin pooprusteek -- -D warnings` (как в CI) и `fmt --check` —
  чисто. `clippy --all-targets` падает на 10 старых замечаниях в чужих файлах
  (`goal.rs`, `providers.rs`, `util.rs`…) — CI его не запускает.

## Не проверено

- Живьём ничего: прогоны были вне объёма. Какой формат модель пишет сейчас и
  насколько выросла доля успешных ходов — неизвестно. Первый шаг при
  возможности: `suite live --repeat 5` до/после.
- Маршрутизация `THINK`: формат событий восстановлен по коду, трасс нет. Если
  начало ответа окажется в неожиданной форме, ответ уйдёт в рассуждения и будет
  отдан ответом только в конце потока (без живого показа).

## Сознательные отступления

В `.docs/tool-call-formats.md`; сверх записанных там: FunctionGemma — значение в
`<escape>` остаётся строкой (vLLM дополнительно разбирает JSON); MiniMax M3 —
листья строками, без приведения по схеме; pythonic — позиционный аргумент
ошибка (эталоны его молча пропускают).

## Грабли

- Heredoc в Bash превратил `\\n` в Rust-литерале в `\n` — тест упал на
  настоящем переводе строки в JSON. Исходники — только через запись/правку.
- Два семейства с одинаковой именованной группой (`(?P<to>…)`) не дали собрать
  общую регулярку сканера — паника во всех тестах разбора. Сканер теперь
  превращает именованные группы маркеров в незахватывающие.
- `STATUS_STACK_BUFFER_OVERRUN` и `rustc-LLVM ERROR: out of memory` при сборке —
  память среды, не код; `-j 1` и повтор.
