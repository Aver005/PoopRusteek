# 2026-11-07 · Финальный заход: блокеры безопасности и миграции

Источники: итоговые ревью безопасности и регрессий `feature/gateway-release` (`ab9a556`).
Каждая находка сверена по коду до правки; ложных нет, часть закрыта не полностью (см. «Не сделано»).
Каждая правка с тестом; для M2, M3, M4, M6, major-3 тесты проверены подменой — на старом поведении они падают
(`scratchpad/mutate.py`: снят замок/проверка/метка, прогон дал 20 красных тестов и одно зависание (`secrets set` ждёт терминал); код восстановлен из копий).

## Решения ведущего (выполнены)

- **M2 (`bash` подтверждает доверие).** `trust` (подтверждение), `secrets set|rm|bind` требуют stdin и stderr — TTY
  и отсутствие `POOPRUSTEEK_AGENT_CHILD` (`secrets/human.rs::require_human`). Переменную ставят: передний план, фон и
  PTY инструмента `bash`/`powershell` (`tools/shell.rs`, `tools/background/spawn.rs`) и stdio-серверы MCP
  (`mcp/transport.rs`). PTY-ребёнок с настоящим TTY всё равно отказывает — проверено тестом на Unix (на Windows
  вывод ConPTY путает UTF-16-эвристику `sanitize_terminal_output`, тест там пропущен; строка с переменной общая).
  `secrets set` из канала больше нет (решение ведущего), `list` и `test` скриптам доступны. `--yes` только пропускает
  вопрос. Команды `bash`/`powershell` с `pooprusteek trust|secrets`, `.pooprusteek`, `pooprusteek/config.toml` и
  настоящими папками конфига (`tools/sensitive.rs`) идут с `always_ask`: белый список не действует, первой строкой
  окна причина (`agent/tools_step.rs::build_approval`). Это смягчение: сброс переменной, переименованная копия
  бинаря, склейка строки из переменных обойдут; прямая правка файла из `bash` остаётся. Сказано в `.docs/secrets-and-config.md`.
- **M3 (CSRF на `/serve`).** Любой запрос с `Origin` отклоняется (403, без CORS-заголовков), если это не loopback-имя на
  порту сервера, не имя самого сервера и не запись `allowed_hosts` (любой порт); ключ не отменяет проверку. Все POST —
  только `Content-Type: application/json` (параметры/регистр допустимы), иначе 415. Клиенты OpenAI SDK и
  `/v1/embeddings` `Origin` не шлют и шлют JSON — не затронуты (тест настоящим HTTP). Разрешённая страница получает
  `Access-Control-Allow-Origin` = её `Origin` и `Vary: Origin`. Старый тест `cors_never_exposes_…` ждал, что чужая
  страница с ключом пройдёт, — переписан под новый контракт (403).
- **M4 (отзыв доверия не отзывает `/serve`).** Строка `sync_server_gateway()` в конце `restart_gateway`
  (`app/gateway_view.rs`; правка в одну строку в файле другого агента — иначе решение невыполнимо). Остальные пути
  пересборки уже синхронизировались. Тест уровня `App` (`app/mod.rs`): живой сервер, пересборка в «выключен»,
  `GET /v1/models` — пусто. Не сделано: при `Starting` сервер по-прежнему видит старый движок до готовности нового.
- **M6 (MCP из чужой папки).** Все восемь источников разобраны: только `mcp.config.json` и `.vscode/mcp.json` в
  папке запуска лежат в проекте; остальные шесть — файлы пользователя (свой `mcp.json`, `pooprusteek/mcp.config.json`,
  opencode, Claude CLI, Claude Desktop, VS Code, Cursor). Файлы проекта: путь + SHA-256 в `[trust.projects]`, тот же
  `pooprusteek trust` (показывает команды, URL и имена `env`, значения и заголовки — никогда), разбор по тексту, с
  которого посчитан хэш (`mcp/project.rs`, `ConfigSource.project_mcp`, реестр подтверждённых текстов обновляет каждая
  загрузка конфига, поэтому `/mcp reload` подхватывает подтверждение). Первый неподтверждённый файл попадает в
  `ConfigSource.pending_trust`, если у проектного конфига запроса нет: существующий диалог доверия (`gateway_view.rs`)
  показывает MCP-файл без правок, `Config::pending_trust_requests()` отдаёт всё списком для нового диалога. Заметка при
  запуске: «This project offers MCP servers (…) that were not started. Review them and run `pooprusteek trust`».
  `trust --revoke` снимает подтверждение со всех файлов проекта. HTTP/SSE из проекта — тоже за подтверждением.
  Изоляция: при `--config`/`--data-dir` пять пользовательских источников не читаются, свой `mcp.json` — только из
  заданной `--data-dir` (`mcp/config.rs::active_sources`; тест на папках-заглушках `Roots`). Побочная правка:
  `load_global_config` при отсутствии папки конфига читал `./pooprusteek/mcp.config.json` от текущей папки — теперь
  пропускается. `AGENTS.md`/`CLAUDE.md` проекта идут в недоверенном конверте (проверено, не менялось).
- **major-3 (гонка первых запусков).** `choose_data_dir` берёт замок `new/.migrate.lock` (ожидание 75 с, держатель
  «стучит» после каждого файла, брошенный — 60 с); второй запуск после ожидания видит метку и берёт ту же папку; не
  дождался — новую (не старую). Метка хранит `started_ms`; пока в старой папке есть переносимый файл новее — слияние
  повторяется (свежее побеждает, проигравший `.legacy`), при неудаче работа остаётся в новой, метка не обновляется.
  Тесты: гонка, таймаут, падение посреди (брошенный замок + частичная копия), дописанное старым бинарём,
  неудачное дополнение.
- **major-2 (деинсталляторы).** `.iss`: спрашивает и удаляет `%LOCALAPPDATA%\pooprusteek` и прежнюю
  `%APPDATA%\pooprusteek` (один вопрос, обе папки в тексте); отдельным вопросом (по умолчанию «нет») — только
  `config.toml`, `.pre-gateway`, `.lock` в `~\.pooprusteek`, правила, скиллы и входы аккаунтов остаются. `install.sh`:
  те же пути данных (Linux новая папка данных = прежняя), вопрос про файл настроек в `~/.pooprusteek`.
  Не проверено запуском: `iscc` на машине нет, `bash -n` проходит.
