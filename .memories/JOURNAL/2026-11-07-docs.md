## Два сценария

### `reads-project-instructions`

Падал на `develop` и в релизе: `files` 1 вместо 2. Причина — ожидание написано
до герметичной рабочей папки харнесса. С 2026-09-06 драйвер грузит правила с
`instructions::Scope::WorkspaceOnly`: только сама рабочая папка, без подъёма к
корню репозитория и без `~/.pooprusteek`. В шаблоне ровно один `AGENTS.md`,
`first_in_dir` берёт один файл на папку, поэтому правда — **1 файл**. Сценарий
теперь требует `files = 1` и `bytes >= 1` (пустой файл `read_rules` отбрасывает,
так что ноль поймал бы потерю секции). Комментарий переписан на правду.

### `rung-one-clears-tool-output`

Журнал релиза сообщал «нет `harness.context.window`». По коду запись делает
`harness/driver.rs` при `AppEvent::ContextWindowLearned`; событие приходит из
фонового `provider.context_window()` (у мока `GET /models` отдаёт
`context_length` 32768). Сценарий сам называет окно через `[context] window`,
поэтому ответ провайдера для раунда 1 не нужен, а ожидание зависит от гонки:
быстрый ход может закончиться раньше, чем придёт событие. Это дефект ожидания,
а не лестницы. Блок убран; раунд по-прежнему доказывают `context.prune` с
`cleared >= 1` и `harness.context.tool_output_cleared`, `spill_failed = 0` и
`context.prune.skipped` с `max_count = 0`.
