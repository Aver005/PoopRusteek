# 2026-07-07 — Landing / input / status-bar layout fixes

Four reported visual defects on the landing screen (from a wide-terminal
screenshot), all layout-math bugs in the TUI render layer. No behavior change
beyond geometry + one status-bar label.

## FIXES

- **Input first line hugged / cursor spilled past the right edge.**
  `build_visual_lines` wrapped at `width − indent` with no right margin, so a
  full first line filled to the last column and the cursor clamp
  (`area.width − indent`) put the caret one cell *outside* the box. Added a
  `RIGHT_MARGIN` (1) reserved in both the wrap width and the cursor clamp.
  (`src/tui/widgets/input.rs`)
- **Wrapped / continuation lines were indented one column past the first.**
  The `" >  "` prompt is 4 wide but continuation lines used a **5**-space
  indent (and `build_visual_lines` / `cursor_pos_inner` matched that 4-vs-5
  split). Unified everything on a single `GUTTER = 4`; removed the now-dead
  `cursor_visual_in_logical`. First and subsequent lines now start in the same
  column.
- **Recent-sessions date clipped to "Jul".** The row concatenated
  id(≤17)+title(≤31)+model(unbounded)+date(12) ≈ 84 cols into a 76-col table,
  so the Paragraph truncated the trailing date. Rewrote `render_sessions_table`
  to budget columns to the (centered) width: fixed id/model/date slots, `title`
  flexes to fill the remainder, `RIGHT_PAD` keeps it off the last column. New
  `util::fit_col(s, width)` truncates-with-… **and** pads to an exact display
  width (multibyte-safe via `UnicodeWidthStr`) — Cyrillic titles stay aligned.
- **Bottom-right "2026-07-" looked like a cut-off date.** It was
  `session_prefix` = first 8 bytes of a `create_session_id` timestamp id
  (`2026-07-04T23-32-11-123Z-<uuid8>`) — not width-clipped, just a misleading
  slice. New `view_model::session_label` parses the leading `%Y-%m-%dT%H-%M-%S`
  and renders `"MMM DD HH:MM"` (e.g. `Jul 04 23:32`); non-timestamp ids fall
  back to `session_prefix`. Status bar now uses it.

## NOTES

- `GUTTER` / `RIGHT_MARGIN` are consts in `input.rs`; the `" >  "` and `"    "`
  prefix literals must stay 4 wide to match `GUTTER`.
- Tests added: `util::fit_col_*` (pad/truncate, multibyte), `view_model::
  session_label_renders_timestamp_ids_as_dates`. Full suite 398 pass, fmt +
  clippy clean.
- The landing input box is `min(width, 76)`; the chat-view input is full width.
  Both call the same `render_input`, so all four input/gutter/margin changes
  apply to both.

# 2026-07-07 (pt.2) — Frozen agent on malformed tool_use + orphaned powershell

Two independent bugs from one user report ("агент перестал что-либо делать",
then 6 `powershell.exe` stuck under the parent shell after a force-close).
Diagnosed from a saved session (`.dev/…59f8cfe3.json`), the two
`tool_parser: Failed to parse <tool_use> body: expected value at line 1
column 1` log lines, and the real model output pulled from the DeepSeek share
via Playwright.

## ROOT CAUSE

DeepSeek emitted a `<tool_use>` block to run `Start-Process
"C:\Users\Aver\strawberry_highlighted.png"` **twice malformed**:
1. swapped closing tags — `…</tool_use>` *before* `</arguments>`. `XML_TOOL_RE`
   (non-greedy) cut the body at the first `</tool_use>`, so `<arguments>` had no
   closer, `XML_ARGS_RE` missed, the code fell to the bare-JSON branch, and
   `serde_json` on a body starting with `<name>` gave *exactly* "expected value
   at line 1 column 1".
2. invalid JSON — unescaped quotes around the Windows path
   (`"Start-Process "C:\…""`).

`parse_tool_calls` **silently dropped** both (a `tracing::warn` to the log file
nobody watches), `strip_tool_calls` erased the block, and the runner saw
`tool_calls.is_empty() && visible_text.is_empty()` → `AgentDone` with nothing
shown, nothing run. Every following user turn repeated it → "frozen".

The same unbalanced quote is *also* why powershell hung: passed to
`powershell -Command`, an unterminated string blocks waiting for input; the job
is spawned `DETACHED_PROCESS` + `stdin=null`, so it hung detached. Detached jobs
are only reaped by `shutdown_all` (graceful exit) / `shutdown_nonpersistent`
(pre-turn) — a force-close skipped both, orphaning them under the grandparent
shell.

## FIXES

- **Parser tolerance + diagnostics** (`src/agent/tool_parser.rs`). New
  `parse_tool_calls_with_errors() -> (Vec<ParsedToolCall>, Vec<String>)`;
  `parse_tool_calls` is now a thin wrapper (`.0`). New `extract_arguments`
  tolerates swapped `</arguments>`/`</tool_use>`, a dropped `<arguments>`
  wrapper (first `{…}` after `<name>`), and the bare `{"name","arguments"}`
  shape (was only `{"tool","args"}`). **Genuinely broken JSON is NOT repaired**
  (would risk running the wrong command) — it becomes a diagnostic. 5 tests
  added (swapped tags, bad-JSON→error, missing wrapper, name/arguments shape,
  well-formed→no errors).
- **Feed malformed calls back to the model** (`src/agent/runner.rs`). When
  `tool_calls` is empty but `parse_errors` is non-empty, push the raw assistant
  text + a `malformed_tool_feedback()` correction (naming each error + the exact
  required shape + JSON-escaping rule) and `continue` the loop instead of ending
  the turn. Bounded by `MAX_MALFORMED_TOOL_RETRIES = 2`; on exhaustion a system
  message tells the user instead of a blank turn. Works for both provider styles
  (DeepSeek re-sends only the last message = the correction; OpenAI/Anthropic
  replay full history and see the mistake + fix).
- **Windows Job Object, kill-on-close** (`src/tools/background/types.rs`
  `win_job` + calls in `spawn.rs`, features in `Cargo.toml`). A process-wide
  anonymous job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; every pipe child
  (via `child.raw_handle()`) and PTY child (via `OpenProcess(pid)`) is assigned
  to it. When pooprusteek dies — graceful, `taskkill`, or crash — the last job
  handle closes and Windows terminates the whole job tree. Assignment failure is
  non-fatal (falls back to the existing `shutdown_all` reaping). Needs
  windows-sys features `Win32_Foundation`, `Win32_Security` (gates
  `CreateJobObjectW`), `Win32_System_JobObjects`, `Win32_System_Threading`.

## NOTES

- Full suite **406 pass**, fmt + clippy clean, ort links.
- The unbalanced-quote → PowerShell-hang is a model/prompt misuse (opening a
  file should be foreground, not `background=true`); left as-is since the Job
  Object now guarantees cleanup regardless. Could later add a heuristic to keep
  fire-and-forget `Start-Process`/`Invoke-Item` in the foreground.
