# 2026-09-29 — идеи из opencode-deepseek: tools на сервере, продолжение обрыва, режимы

Источник — клон `.dev/opencode-deepseek` (Python-мост «веб-DeepSeek → OpenAI API
для opencode», ~2000 строк). Почти во всём мы сильнее (парсер, промпт, сессии,
заголовки). Взяты три идеи; две из них пришлось доделывать живьём.

## Что сделано

1. **`tools` в `/serve`.** Раньше сервер выбрасывал `tools` с предупреждением.
   Теперь `server/tools.rs` (`ToolBridge`): схемы клиента — JSON целиком в
   системный промпт (плоский `format_tool_definition` терял бы `enum` и
   вложенность), формат `<tool_use>`, напоминание последним сообщением,
   `tool_choice` (`auto`/`required`/`none`/конкретный). Ответ разбирает
   `agent::tool_parser` — клиент получает `tool_calls` из любого формата,
   включая DSML. История клиента: `tool_calls` ассистента → текст `<tool_use>`
   (`flatten_history`), имя результата — по id вызова (`openai_compat::tool_name_for`).
   Стрим с инструментами копится целиком, пока копится — `: keep-alive` раз в 10 с.
   Эмуляция одна для всех бэкендов: родной tool calling у записей недоделан
   (запросы шлются, вызовы из ответа не разбираются ни одним клиентом).
2. **Продолжение оборванного ответа.** Два уровня:
   - провайдер DeepSeek: статус `INCOMPLETE` → родное «Продолжить»
     (`send_continue`, до 3 раз, одно сообщение ассистента); не вышло →
     `finish_reason: "length"`;
   - общий (`agent/continuation.rs`): вызов, оборванный в конце ответа
     (`ParsedReply::cut_at`), дописывается просьбой «продолжи с символа» и
     склейкой; работает для любого провайдера — в цикле агента, суб-агенте и
     на сервере.
3. **Режимы DeepSeek из id модели** (`deepseek/mode.rs`): модель
   (`chat`/`expert`), `-think`, `-search` — независимо. `deepseek-reasoner` =
   Expert + DeepThink, как было.

## Живые находки (тестовый аккаунт, `exec` + Chrome DevTools)

- **Обрыв по лимиту шёл как успешный `stop`.** Сервер пишет
  `{"p":"response/status","o":"SET","v":"INCOMPLETE"}` (и `quasi_status` в
  BATCH), поток этого не знал. Лимит вывода — около 16–17 КБ текста на ответ.
- **Запрос «Продолжить» снят с веб-клиента:** `POST /api/v0/chat/continue`,
  тело `{"chat_session_id", "message_id", "fallback_to_resume": true}`,
  **без PoW**. Поток открывается снимком всего ответа (прежний текст плюс
  начало нового) — без `SnapshotSkip` первая часть дублировалась бы.
- **Шов теряет символы по вине модели.** Даже родное продолжение сайта
  выдало `30643065` (пропущен `\n`); промптовое — `57875788`. Детерминированно
  это не чинится. В прогоне с родным продолжением шов вышел чистым (6000 строк
  подряд) — одна попытка, не статистика.
- **Модель закрывает склеенный вызов `}}`.** Грамматика `<tool_use>` теперь
  прощает лишние `}` перед закрывающими тегами — другой мусор там по-прежнему
  ошибка.
- Режимы: Instant + `-think` даёт фрагменты `THINK`, Expert без `-think` — нет;
  флаги уходят независимо. С `-search` модель поиск не запустила
  (`search_triggered: false`) — формат фрагментов поиска **не видели**.
- `/serve` на DeepSeek: запрос в стиле opencode → `tool_calls` с
  `finish_reason: "tool_calls"`; второй ход (история с вызовом и результатом,
  стрим, `deepseek-expert`) → ответ текстом, keep-alive был.

## Ошибки по ходу

- Первый признак обрыва («битая находка дошла до конца текста») ловил и
  закрытый битый вызов в конце ответа — упал тест
  `a_broken_call_beside_a_good_one_is_reported_to_the_model`. Теперь проба:
  к тексту дописывается хвост, оборванным считается вызов, который его
  проглотил (`scan::cut_off_at_end`).
- `join` сначала пробовал склейку, и перезапущенный моделью вызов давал
  «закрытый битый» вместо целого. Порядок обратный: сначала «модель начала
  заново» (тот же маркер в начале куска), потом склейка.

## Не сделано / открыто

- Родной tool calling для записей (`ToolProtocol::Native`) — клиенты не
  разбирают `tool_calls` из ответа; сервер сейчас эмулирует и для них.
- Формат фрагментов веб-поиска.
- Автоподхват токена из браузера (как у моста через Playwright) — не брали.
