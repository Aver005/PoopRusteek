# 2026-09-13 — установщики, стабильные релизы, каналы обновлений

Запрос владельца: людям нужен установщик, а не голый exe в релизах — «красивый,
быстрый, без лишних этапов». Выбор папки важен тем, что туда же идут
переустановка, удаление и автообновление. Автообновление должно брать версии
по тегу, а не каждый коммит. Выпуск тега — одной командой. Платить за подпись пока не готовы.

## Что было на самом деле

Предположение «CI собирает только exe, zip кладу руками» не подтвердилось.
`ci.yml` уже собирал Windows x64, Linux x64 и macOS arm64 на каждый пуш в develop
и публиковал два prerelease: `v0.1.0-dev` и `latest`. Ручного скрипта не было.
Настоящие пробелы:
- стабильных релизов нет, ручной тег `v0.1.0` стоит без файлов, кроме zip;
- обновлятор ставил любой develop-коммит по несовпадению хэша и мог откатить назад;
- установщиков нет;
- release-бинарник читал промпты и wasm из текущей папки и по пути сборки раньше встроенных копий.

## Решения

- **Windows — Inno Setup 7**, а не cargo-dist, WiX или Velopack.
  - MSI у cargo-dist — это стандартные диалоги WiX v3 и установка в Program Files,
    где `/update` не может писать.
  - Velopack сделан под GUI: `.app`, AppImage, без PATH.
  - Inno даёт per-user установку без UAC, тему по системе и один экран.
- **macOS/Linux — `install.sh`**. Скачанное через `curl` Gatekeeper не карантинит,
  поэтому подпись Apple на старте не нужна.
- **Каналы.**
  - `stable` = GitHub «Latest», URL `releases/latest/download/…` работает без
    отдельного тега (сверено по документации GitHub); ставится только более новая версия.
  - `dev` = rolling-тег `dev`, ставится по хэшу.
  - Версию и хэши несёт `manifest.json`, а не API GitHub: без лимитов и без
    зависимости от формата ответа.
- **Legacy-мост.** Сборки ≤ 0.1.0 умеют только `latest/SHA256SUMS`, поэтому стабильный
  релиз обновляет и старый тег `latest`. Удалить в 0.3.0.
- **Скрипт релиза публичный** (`scripts/release.sh`): секретов в нём нет, только git и cargo.
- **Модель эмбеддингов** на установке не качается: лишняя зависимость, нужна не всем.
- **arm64 Windows и Linux** добавлены экспериментальными: у `ort` есть prebuilt ONNX Runtime,
  но в CI эти раннеры ещё не обкатаны.

## Ревью

Три независимых агента разобрали код обновлятора, CI со скриптами и сквозной сценарий.
Подтверждённое и закрытое:
- **Повторный `/update` в том же процессе.** Stable сравнивал с константой
  `CARGO_PKG_VERSION` и качал заново. Дальше на Windows падал на занятом `.old`,
  на Linux писал файл `pooprusteek (deleted)` (путь `/proc/self/exe` после rename).
  Закрыто флагом `INSTALLED_THIS_RUN` → `PendingRestart`; ещё до решения о замене
  сравнивается хэш файла на диске.
- **Stable до первого тега отдавал 404** на каждом старте с `/autoupdate on`.
  Теперь `NoRelease`, при автопроверке молча.
- **`release.sh` упал бы на втором релизе**: `git fetch --tags` отказывается
  перезаписать локальный `dev`/`latest`, которые CI переносит с `--force`.
- **`render-release-notes.sh`**: в bash 5.2 `&` в `${text//tok/val}` подставляет найденное,
  `{{TAG}}` из текста коммита подставлялся повторно. Переписан на однопроходный разбор.
  Кавычки вокруг значения не спасают: `\\` всё равно схлопывается.
- **`install.sh`**:
  - падал без `$SHELL` под `set -u`;
  - затирал рабочий бинарник до проверки `--version`;
  - при удалении оставлял строку PATH, если в rc больше ничего не было, и превращал
    симлинк rc в обычный файл;
  - при смене `--dir` врал «Added to PATH».
- **Установщик**:
  - переустановка с другой папкой оставляла старую копию первой в PATH → `DisableDirPage=auto`;
  - переустановка поверх запущенного приложения → `AppMutex` + мьютекс в `main`;
  - папка без прав записи → проверка в `NextButtonClick`;
  - старый setup поверх новой версии → предупреждение в `InitializeSetup`.
- **Delete → create релизов** оставлял канал пустым, а `cancel-in-progress` мог прервать
  публикацию между шагами. Теперь релиз обновляется на месте, манифест грузится последним,
  отмена — только для PR.
- **Порядок пререлизов** был строковым (`rc.10 < rc.2`) → SemVer §11. `release.yml`
  не пускает пререлиз в «Latest».
- **Мелочи**:
  - тег `..` в манифесте;
  - «нет сборки» вместо «битый хэш»;
  - `.old` занят вторым экземпляром → `.old.<pid>`;
  - `git describe` мог взять `v0.1.0-dev` → `--exclude '*-*'`;
  - legacy-шаг отделён в свою джобу.

### Второй раунд — проверка исправлений

Отдельный агент прошёл каждое исправление в обе стороны: 8 из 10 чистые, два дали новые дефекты.
Закрыто:
- **`install.sh --uninstall`** при заданном `--dir` без бинарника удалял **чужой**
  `pooprusteek` из PATH (воспроизведено на cargo-копии в `~/.cargo/bin`). Теперь поиск
  через PATH — только без `--dir` и только с подтверждением.
- **Проверка `--version`** запускалась из `mktemp` → на `noexec /tmp` ложный отказ
  «нужен glibc». Теперь проверяется копия `.new` в папке установки.
- **`render-release-notes.sh`** падал на `{{}}` (`bad array subscript`).
- **Установщик**:
  - сообщение о папке без записи не подавлялось в `/VERYSILENT` → `SuppressibleMsgBox`;
  - проба оставляла цепочку пустых папок → удаляется самая верхняя созданная.
- **`install.sh`** копил пустые строки в rc при каждой смене `--dir`.

## Как проверено

- `cargo test --bin pooprusteek`: 892 passed. `cargo clippy --bin pooprusteek -D warnings`: чисто.
- Установщик скомпилирован Inno Setup 7.1.0 (временная per-user установка
  во временной папке сессии): с одним x64 и с x64+arm64. Сам мастер **не запускался** — это смоук.
- `release.sh` прогнан в клоне с bare-remote:
  - dry-run, отказ на старой версии;
  - откат при падающем хуке;
  - успешный релиз;
  - релиз при сдвинутом удалённом `dev`.
- `make-manifest.sh`, `changelog-section.sh`, `render-release-notes.sh`,
  `install.sh --help/--uninstall` — на временных файлах.
- **CI не запускался**: пуш — решение владельца. Первый прогон `build.yml` покажет
  arm64-раннеры и установку Inno в CI.

## Попутные находки (не чинились)

- `Cargo.lock` лежал в `.gitignore` → релизы не воспроизводимы. 2026-09-14 владелец согласился:
  lock-файл закоммичен, все cargo-команды CI идут с `--locked`.
- `cargo clippy --bin pooprusteek --tests -D warnings` падает на старом коде
  (`items_after_test_module`, `no_effect_replace`, `edit_for_test` never used и др.).
  CI гоняет clippy без `--tests`, поэтому не видно.
- У exe нет иконки — мастер установки и «Приложения» показывают стандартную.

## 2026-09-14 — первый прогон CI

- **Коммит `7353438`:** fmt/clippy, Ubuntu и Windows зелёные; тесты на macOS упали.
  Сборка и dev-публикация пропущены.
- **Причина** — не macOS, а дыра в охране записи, которую тесты на Linux пропускали
  случайно. Подробности в `BUGS.md` (RESOLVED 2026-09-14).
- **Вывод** про добавление macOS в тестовую матрицу: новая ОС в матрице — это новые
  условия для старых тестов. Симлинк в пути временной папки на macOS вскрыл дефект,
  который год бы прожил на Linux.

- **Второй прогон (`00b301b`):** тесты зелёные на всех трёх ОС, но упала упаковка —
  `package.sh` копировал в архив `LICENSE`, а файла в репозитории **нет** (при
  `license = "MIT"` в `Cargo.toml`). Корень ошибки: существование файла выведено из
  `paths-ignore: LICENSE` в `ci.yml`, а не проверено. Теперь документы кладутся в архив,
  только если они есть. `LICENSE` (MIT, Artemiy Averyanov) добавлен по решению владельца.
