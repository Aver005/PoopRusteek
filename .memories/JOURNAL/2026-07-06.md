# 2026-07-06 — API server mode (`--serve` / `/serve` / `/server <port>`)

## WHAT SHIPPED

The P1 "OpenAI-compatible server mode" from PLANS.md, end to end. pooprusteek
now runs a local HTTP gateway that exposes **every configured provider**
(built-in DeepSeek web client + all `/providers` entries) behind one
OpenAI-compatible endpoint, so aider/Continue/OpenWebUI/anything can use it
as a backend.

Owner spec: start via `--serve` | `--server` | `--api` flags; in-TUI
`/serve` (status) / `/serve on|off` / `/server <port>` (port persisted for
all future runs); OpenAI-compatible in/out; design so the exposed API
dialect can later switch between OpenAI / Anthropic Messages / Generative
Language.

## PIECES

- `Cargo.toml`: `hyper` 1 (server+http1) + `hyper-util` (tokio) +
  `http-body-util`. Deliberately no axum — 3 routes don't justify the tower
  stack, and hyper was already in-tree via reqwest.
- `config`: new `[server]` table — `host` (default `127.0.0.1` — loopback
  on purpose), `port` (default **7667** = "poop" on T9), `api`
  (`ServerApi::{Openai,Anthropic,Gemini}`, only Openai implemented —
  others parse but answer 501; the extensibility seam the owner asked
  for), `api_key` (optional bearer). Back-compat parse test.
- `src/server/` (new):
  - `catalog.rs` — pure model routing. Ids: `deepseek-chat`/`-reasoner`,
    `deepseek/<m>`, `<entry>/<model>` (**sub-model override** — the entry
    is cloned with the requested model, so any upstream model is reachable,
    not just the configured one), bare `<entry>`, bare configured model.
  - `http.rs` — bind with 10×100ms retry (absorbs the restart race when
    `/server <port>` replaces a listener), accept loop (`JoinSet`,
    shutdown `watch`), bearer auth, permissive CORS, `/health`, dialect
    dispatch. Lifecycle events are **generation-tagged** so a replaced
    server's late `ServerStopped` can't clear its successor's handle.
  - `openai.rs` — `GET /[v1/]models`, `POST /[v1/]chat/completions`
    (16 MiB body cap). Stateless per request: `fork()` per call; DeepSeek
    forks get `discard_remote_session()` after every completion (streaming
    included) — API traffic leaves no junk chats. SSE bridge re-frames
    provider chunks under one `CompletionMeta` (`role` on first delta,
    terminal `finish_reason` chunk, literal `data: [DONE]`); client hangup
    aborts the upstream task. Inbound `tools` are warned about (tracing)
    and ignored, not rejected — many clients always send them.
- `app/serve.rs` (new) — `apply_serve_action` (`CommandResult::Serve` from
  dispatch.rs), `start_server` (pub; `--serve` calls it from main),
  restart-on-port/dialect-change, `/serve` status text (state, addr,
  uptime, request/error counters from `ServerStats` atomics, model list).
- `commands/defs/serve.rs` — `ServeCommand` + `ServerCommand`, parsing kept
  as pure `parse_serve_args`/`parse_server_args` (tested without AppState).
- `provider/mod.rs` — extracted `build_entry_provider(entry)` from
  `build_provider` (server builds per-request instances for sub-model
  overrides).
- `openai_compat.rs` — module-level `#![allow(dead_code)]` removed; the
  "planned server mode" doc header rewritten to point at `crate::server`.

## VERIFICATION

- 358 tests (was 345), clippy 0, test-profile warnings 0.
- `server::http` E2E over a real socket: lifecycle events, `/health`,
  401-without-bearer → 200-with, empty model list, `model_not_found`
  envelope, 400 on bad JSON, 404 on unknown path, shutdown event.
- `server::openai` E2E: mock OpenAI upstream (hyper, port 0) behind a
  `/providers` entry — non-streaming round trip (`mock/custom` echoes the
  caller's id while the upstream receives `custom`; real usage passes
  through) and streaming round trip (delta framing, finish_reason, [DONE]).

## GOTCHAS / DECISIONS

- `OpenAiCompatProvider` (and the anthropic/gemini clients) send **their
  entry's configured model**, ignoring `CompletionRequest.model` — that's
  why sub-model override works by cloning the `ProviderEntry` with a
  swapped model and building a fresh per-request provider, NOT by setting
  `request.model`.
- DeepSeek backend is built once per server launch and `fork()`ed per
  request → all API traffic shares one rate limiter.
- Pre-existing test-profile warnings fixed in passing: unused `config` in
  `session.rs` test; `AgentResult`'s `#[expect(dead_code)]` → `allow`
  (under `cargo test` the fields count as read, unfulfilling the expect —
  same reasoning as the old openai_compat header note).
- Errors after the SSE 200 has been committed travel in-stream as a
  `data: {"error": …}` line (standard proxy convention).
- Provider changes made while the server runs need `/serve off` + `on`
  (settings are snapshotted at launch) — the status text says so.

## FOLLOW-UPS (also in PLANS.md)

- Anthropic/Gemini inbound dialects (501 today; outbound conversions
  already exist in `provider/{anthropic,gemini}_compat`).
- Optional agent-loop-backed completions (v1 bypasses tools by design).
- Maybe surface a server indicator in the status bar / stats panel.

# Session 2 (2026-07-06): BLAZE perf pass — startup, streaming, render, persistence

Four staged optimizations, hard constraint: zero functional/behavioral
change. Tests 358→364, clippy 0 throughout.

## Stage 1 — first frame no longer waits on MCP

- `App::new` used to `mcp_manager.initialize().await` before `run()` drew
  anything → one unreachable HTTP server = up to ~60s blank terminal.
- New `mcp::manager::startup_initialize(&Mutex<MCPManager>)` (free fn):
  4 phases, lock held only for short await-free merges — (1) no lock:
  discover configs + build ALL clients concurrently (`join_all`; the old
  serial `add_server` loop stacked keyring lookups per HTTP/SSE server);
  (2) short lock: insert entries as Pending/Disabled; (3) no lock: the
  existing `connect_one` jobs concurrently; (4) short lock: merge.
  Spawned from `App::new`; sends new quiet `AppEvent::McpInitialized`
  (refreshes `mcp_status` counters; semantic MCP corpus updated in the
  task itself). `MCPManager::initialize` deleted (was single-caller).
- Guard added: `apply_connect_outcome` now skips servers removed/disabled
  between the lock-free connect and the merge (startup races /mcp
  remove/toggle; old single-lock callers can't hit it).
- Known nuances (accepted): a message sent in the first seconds may build
  its system prompt before MCP tools exist (previously impossible since
  UI wasn't up); `--acp` unaffected (doesn't use `App::new`).

## Stage 2 — streaming O(n²) killed twice

- `agent/tool_parser.rs`: new `StreamTextTracker` replaces per-chunk
  `stream_visible_text(full_response)` in `run_agent_loop` (three regex
  `replace_all` over the whole accumulated text per SSE delta). Freezes
  the input prefix whose STRIPPED form is provably final; regex passes run
  only on the hot tail; the cheap truncation stays global per call
  (a `[TOOL:` cut marker can be spliced across the frozen/hot seam by a
  stripped block — found while designing, has a test). Freezing rules are
  pass-order-aware (XML→thinking→legacy): thinking blocks freeze only if
  free of `<tool_use>`, legacy only if `<`-free, lone `<`/`[` freeze once
  a 9-byte `<`-free window diverges from every opener.
  `stream_visible_text` kept as `#[cfg(test)]` ground truth;
  `tracker_matches_full_pipeline_on_every_prefix` asserts byte-identical
  output at EVERY prefix over adversarial cases. Degrades to old O(n²)
  (never wrong output) on e.g. `<<` early in the stream.
- `tui/markdown.rs`: `HIGHLIGHT_CACHE` memoizes syntect per code block
  (key: code+lang+`theme.warning`; syntect theme is fixed). While
  streaming, the whole in-progress message re-renders every frame and
  used to re-highlight every COMPLETED block each time — syntect
  dominates render cost. Caps: 128 entries (wipe-on-overflow), 64 KiB max
  block. No-lang blocks skip it (no syntect involved).

## Stage 3 — render_chat: cached heights + viewport culling

- `tui/widgets/chat.rs` restructured into two passes:
  counting pass = per-message wrapped row counts only (no line building,
  no clones); materializing pass = build lines ONLY for messages
  intersecting the viewport, `Paragraph::scroll` by the offset into the
  first visible message (incidentally fixes >65535-row transcripts
  overflowing the u16 scroll arg).
- `CachedMsg` gained `meta_rows`; new `ROWS_CACHE` for non-assistant
  bubbles (fingerprint ^ role-tag guards popped-slot collisions). Row
  math kept byte-identical to the old accumulation (assistant header
  still counted as 1 row — same narrow-width inaccuracy as before, by
  design). Old `render_assistant_cached` → closure-style
  `with_assistant_cached` so the counting pass never deep-clones cached
  lines; NB: replaced my initial `entry().or_insert()` with plain
  `insert` — or_insert would keep a stale entry on fingerprint mismatch.
- Shared `build_segment_lines`/`assistant_header`/`is_markdown_assistant`
  so counting and materializing can't disagree on shape.

## Stage 4 — persistence off the event loop

- New `app/persist.rs`: `Persister` = unbounded mpsc → one worker task →
  `spawn_blocking` per job, strictly FIFO. Ordering is load-bearing:
  jobs are full snapshots (newest must be last write to a path) AND
  `util::atomic_write` uses a fixed sibling `.tmp` (concurrent writes to
  one file would clobber each other's temp).
- `auto_save_session` (ran `save_session` synchronously in `handle_event`
  on AgentDone/AgentError — full pretty-JSON rewrite growing with the
  conversation) now snapshots and enqueues; semantic `index_session`
  moved into the worker on save success (same coupling as before).
- `session::append_history` split: `push_history_entry` (pure in-memory
  transform — dedup-consecutive + cap 500) + `write_history` (blocking
  write). `keys/chat.rs` updates `state.input.history` in memory first
  (up-arrow sees the entry immediately — the old code re-READ the file
  after appending, which an async write would have raced) and queues the
  write. Multi-instance read-modify-write merging is coarser now
  (accepted; was already racy).
- `Persister::flush(3s)` called on app exit (a save queued by the last
  turn must not be lost) and at the top of `execute_wipe` (a queued save
  must not re-create files the wipe just deleted).

## VERIFY

- `cargo test --bin pooprusteek` 364 ok; clippy 0.
- NOT yet visually verified (needs a real terminal + token): streaming a
  long answer with code blocks (stage 2/3), scrolling a 200+ message
  transcript, startup with a slow MCP server. Semantic ranking untouched
  (no MRR re-run needed).

## POST-SESSION FIX — startup input lag (user report)

User reported hard input lag while typing fast, persisting after MCP
servers turned green. Investigation (render bench + reading the app's own
`pooprusteek.log` + data dir):

- `render_chat` exonerated: perf probe (`render_chat_perf_probe`,
  `#[ignore]`d test with `TestBackend`) shows ~1.4ms/frame on a
  300-message transcript even in a DEV build.
- Log timeline showed the real culprit: after connects go green, the
  semantic layer embeds 136 skills + 92 MCP tools + history backfill —
  and fastembed/ONNX Runtime defaults its intra-op pool to EVERY core
  (`available_parallelism`), saturating the machine for ~20-60s and
  starving the TUI event loop. Pre-existing since semantic landed
  (2026-07-05), but the instant first frame now invites typing exactly
  inside that window — before, a 13-25s blank-screen MCP wait masked the
  start of it. Amplifier: the user was running the 80 MB dev build
  (`target/debug`, tokenizers ~10-30× slower → longer window); their
  system32 install is a 16 MB release from Jun 27.
- Fix: `Embedder::init` now caps ort intra-op threads to
  `(cores/2).clamp(1, 4)` (`with_intra_threads`, fastembed 5.17.2).
  Background indexing takes longer; single-query turn embeddings are
  unaffected in practice. Ranking math untouched — no MRR re-run needed.

## FOLLOW-UP 2 — first-token latency vs the semantic index lock

The intra-thread cap (above) makes indexing holds LONGER, which made this
overdue: two entry points waited unboundedly on the semantic `inner`
mutex that `rebuild_mcp_corpus` holds for its whole build and the history
backfill holds per-session.

- `match_prompt` (runs before every turn's first provider request): now
  acquires via new `lock_inner_bounded(HINT_LOCK_BUDGET=150ms)` — rides
  out another turn's few-ms query embedding, gives up on an indexing hold
  and the turn goes out hint-less (invariant #11: degrade, never block).
  Worst-case first-token delay from semantics: tens of seconds → 150ms.
- `status()` (called by `/rag` synchronously ON THE EVENT LOOP —
  `rag_status_text` in keys/dispatch.rs): was a straight `lock().unwrap()`
  → `/rag` during a rebuild froze the whole UI for the hold. Now returns
  `Option<RagStatus>` via a single `try_lock`; the caller prints an
  honest "indexing in progress, try again in a few seconds" line.
- `lock_inner_bounded(ZERO)` = one try_lock (event-loop-safe); positive
  budget retries with 10ms sleeps (blocking threads only). Poisoned lock
  → None (used to panic via unwrap).
- Test `busy_index_lock_degrades_instead_of_blocking` holds the lock and
  asserts status declines instantly + match_prompt returns empty within
  budget. Tests 364→365, clippy 0. Ranking untouched — no MRR re-run.

# CI/CD: dev-build rolling release (2026-07-06)

Added two new pipeline files (no changes to `src/` or `ci.yml`):

- `.github/workflows/dev-release.yml` — on push to `develop`
  (`paths-ignore: **/*.md, .memories/**, LICENSE`), builds release binaries
  for windows-latest/ubuntu-latest/macos-latest, then force-moves a
  `v<Cargo.toml version>-dev` tag to the new commit, deletes the old
  release for that tag (`gh release delete`), and republishes via
  `softprops/action-gh-release@v2` with fresh assets. Cargo.toml version
  bump ⇒ new tag/release instead of overwriting. `concurrency:` group
  cancels superseded runs on rapid pushes.
- `.gitlab-ci.yml` — same rolling-tag idea for a future GitLab
  mirror/project (no GitLab remote exists yet, unverified against a real
  pipeline). Linux leg builds on a default shared runner; Windows/macOS
  legs are `when: manual` + `allow_failure: true` behind SaaS runner tags
  (`saas-windows-medium-amd64` / `saas-macos-medium-m1`) since those aren't
  guaranteed to exist for this project — release job uses `needs: optional:
  true` on them so it doesn't block. Needs a `GITLAB_TOKEN` CI/CD variable
  (`api` scope) to delete the previous tag via the Tags API before
  `release-cli create` recreates it (GitLab has no equivalent of GitHub's
  "just force-push the tag ref"). GitLab's `rules:changes` has no docs-
  exclusion negation, so it whitelists `src/**/*`, `Cargo.{toml,lock}`,
  `build.rs`, `.gitlab-ci.yml` instead of blacklisting docs like the GitHub

# Session 4 (2026-07-06): scroll vs. history-recall conflict + mouse wheel

User report: in an active chat the message-window scroll fought the input
history recall — plain Up/Down recalled prompts (when the input was empty /
cursor on the first line) instead of scrolling the transcript.

- **History recall moved to Ctrl+Up / Ctrl+Down** (`keys/chat.rs`),
  unconditionally (dropped the old "no newline before/after cursor"
  disambiguation). Plain Up/Down/PageUp/PageDown now *always* scroll the
  transcript — no more mode-fighting.
- **Mouse wheel → window scroll.** `tui::init` now emits `EnableMouseCapture`
  (`restore` emits `DisableMouseCapture`); trade-off noted in code: terminal
  text selection now needs Shift. New `AppEvent::Mouse(MouseEvent)` routed
  from the `run_loop` select! arm through `handle_event` to a new
  `keys/mouse.rs::handle_mouse` (sync, no I/O — safe on the event loop). It
  dispatches by modal/view exactly like `handle_key`: ToolApproval modal,
  `View::Mcp` details, `View::Search` results (moves selection), else the
  chat transcript. Each direction matches that surface's own Up/Down keys
  (chat `scroll_offset` is rows-from-bottom → wheel-up increases it; MCP is
  from-top → wheel-up decreases). Step = 3 rows/notch.
- Help text (`commands/defs/help.rs`) updated: documents Ctrl+Up/Down recall,
  PageUp/PageDown, and "wheel scrolls too".
- Note: the in-loop `needs_terminal_restore` redraw (mod.rs) doesn't touch
  mouse capture — the DECSET modes are independent of alt-screen and were
  never disabled there, so capture survives the redraw. Fine as-is.

# Session 4 (2026-07-06): gateway v3 — proxy review fixes (reasoning / legacy / embeddings)

External review of the proxy flagged 4 things. Dispositions from the owner:
#4 do, #1 probably-do, #2 discussable (owner suggested a `<think>` wrapper),
#3 explain-only.

## #4 — legacy `POST /v1/completions` (DONE)

Synthesized on the chat path, so it works for EVERY backend incl. the
DeepSeek web client (a raw upstream passthrough would not): prompt (string
or [string]) → one user `ChatMessage` → resolve+run → shaped back as
`text_completion` (`choices[].text`, `logprobs: null`). Stream + blocking
(`legacy_stream`/`bridge_legacy_stream`). `<think>` reasoning is stripped
(legacy has no field for it). `LegacyCompletionRequest`/`LegacyPrompt`.

## #1 — `POST /v1/embeddings` + `/v1/rerank` passthrough (DONE)

Not modelled by pooprusteek → forwarded verbatim to the `/providers` entry
that serves the requested model (the only backend that can answer). `model`
in the body is rewritten to the resolved sub-model; upstream status+body
returned untouched. New `ServerContext.http_client` (reused reqwest client,
10s connect timeout). Guards: built-in DeepSeek → clear 400 ("no embeddings
endpoint"); non-OpenAI-protocol entry → 400; unknown model → 404 (not 502).
Rerank is best-effort (works only if the upstream implements `/rerank`;
Ollama doesn't). Live-verified: bge-m3:567m → object=list, dim 1024.

## #2 — `<think>` → `reasoning_content` (DONE, with a documented limit)

`openai_compat::split_reasoning(content) -> (Option<reasoning>, content)`:
extracts a LEADING `<think>`/`<thinking>` block (only leading — a mid-text
mention is left alone); unterminated opener (finish_reason==length mid-
thought) → all reasoning, empty content. `ReasoningStreamSplitter` does the
same incrementally for streaming — a 3-phase state machine (Start /
InReasoning / InContent) that holds back only a partial-tag-sized suffix, so
normal (non-reasoning) output flows through essentially unbuffered.
`stream_splitter_matches_pure_split_at_every_boundary` feeds every case one
byte at a time and asserts the byte-torn stream equals the pure split.
`reasoning_content` added to `ChatCompletionMessage` + `Delta`;
`response_to_openai` splits (blocking), `bridge_stream` routes reasoning vs
content deltas (streaming) via new `split_delta_chunk`. Consistent with
`agent/tool_parser`'s existing `<thinking>` strip.

LIMIT (deliberate, flagged to owner): this fixes backends that emit inline
`<think>` in content (deepseek-r1 raw, some vLLM/LM Studio). It does NOT fix:
- **DeepSeek web reasoner** — `deepseek/stream.rs::extract_response_fragments_content`
  merges typed THINK fragments into content with NO tags, so there's nothing
  to split. Proper fix needs a reasoning channel on `CompletionChunk`/
  `CompletionResponse` + fragment-index→type tracking in the deepseek stream,
  and it changes the TUI's current inline-thinking display → left as a
  decision.
