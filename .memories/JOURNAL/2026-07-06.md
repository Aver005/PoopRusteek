# 2026-07-06 — API server mode (`--serve` / `/serve` / `/server <port>`)

## WHAT SHIPPED

The P1 "OpenAI-compatible server mode" from PLANS.md, end to end. pooprusteek
now runs a local HTTP gateway that exposes **every configured provider**
(built-in DeepSeek web client + all `/providers` entries) behind one
OpenAI-compatible endpoint, so aider/Continue/OpenWebUI/anything can use it
as a backend.

Owner spec: start via `--serve` | `--server` | `--api` flags; in-TUI
`/serve` (status) / `/serve on|off` / `/server <port>` (port persisted for
all future runs); OpenAI-compatible in/out; design so the exposed API
dialect can later switch between OpenAI / Anthropic Messages / Generative
Language.

## PIECES

- `Cargo.toml`: `hyper` 1 (server+http1) + `hyper-util` (tokio) +
  `http-body-util`. Deliberately no axum — 3 routes don't justify the tower
  stack, and hyper was already in-tree via reqwest.
- `config`: new `[server]` table — `host` (default `127.0.0.1` — loopback
  on purpose), `port` (default **7667** = "poop" on T9), `api`
  (`ServerApi::{Openai,Anthropic,Gemini}`, only Openai implemented —
  others parse but answer 501; the extensibility seam the owner asked
  for), `api_key` (optional bearer). Back-compat parse test.
- `src/server/` (new):
  - `catalog.rs` — pure model routing. Ids: `deepseek-chat`/`-reasoner`,
    `deepseek/<m>`, `<entry>/<model>` (**sub-model override** — the entry
    is cloned with the requested model, so any upstream model is reachable,
    not just the configured one), bare `<entry>`, bare configured model.
  - `http.rs` — bind with 10×100ms retry (absorbs the restart race when
    `/server <port>` replaces a listener), accept loop (`JoinSet`,
    shutdown `watch`), bearer auth, permissive CORS, `/health`, dialect
    dispatch. Lifecycle events are **generation-tagged** so a replaced
    server's late `ServerStopped` can't clear its successor's handle.
  - `openai.rs` — `GET /[v1/]models`, `POST /[v1/]chat/completions`
    (16 MiB body cap). Stateless per request: `fork()` per call; DeepSeek
    forks get `discard_remote_session()` after every completion (streaming
    included) — API traffic leaves no junk chats. SSE bridge re-frames
    provider chunks under one `CompletionMeta` (`role` on first delta,
    terminal `finish_reason` chunk, literal `data: [DONE]`); client hangup
    aborts the upstream task. Inbound `tools` are warned about (tracing)
    and ignored, not rejected — many clients always send them.
- `app/serve.rs` (new) — `apply_serve_action` (`CommandResult::Serve` from
  dispatch.rs), `start_server` (pub; `--serve` calls it from main),
  restart-on-port/dialect-change, `/serve` status text (state, addr,
  uptime, request/error counters from `ServerStats` atomics, model list).
- `commands/defs/serve.rs` — `ServeCommand` + `ServerCommand`, parsing kept
  as pure `parse_serve_args`/`parse_server_args` (tested without AppState).
- `provider/mod.rs` — extracted `build_entry_provider(entry)` from
  `build_provider` (server builds per-request instances for sub-model
  overrides).
- `openai_compat.rs` — module-level `#![allow(dead_code)]` removed; the
  "planned server mode" doc header rewritten to point at `crate::server`.

## VERIFICATION

- 358 tests (was 345), clippy 0, test-profile warnings 0.
- `server::http` E2E over a real socket: lifecycle events, `/health`,
  401-without-bearer → 200-with, empty model list, `model_not_found`
  envelope, 400 on bad JSON, 404 on unknown path, shutdown event.
- `server::openai` E2E: mock OpenAI upstream (hyper, port 0) behind a
  `/providers` entry — non-streaming round trip (`mock/custom` echoes the
  caller's id while the upstream receives `custom`; real usage passes
  through) and streaming round trip (delta framing, finish_reason, [DONE]).

## GOTCHAS / DECISIONS

- `OpenAiCompatProvider` (and the anthropic/gemini clients) send **their
  entry's configured model**, ignoring `CompletionRequest.model` — that's
  why sub-model override works by cloning the `ProviderEntry` with a
  swapped model and building a fresh per-request provider, NOT by setting
  `request.model`.
- DeepSeek backend is built once per server launch and `fork()`ed per
  request → all API traffic shares one rate limiter.
- Pre-existing test-profile warnings fixed in passing: unused `config` in
  `session.rs` test; `AgentResult`'s `#[expect(dead_code)]` → `allow`
  (under `cargo test` the fields count as read, unfulfilling the expect —
  same reasoning as the old openai_compat header note).
- Errors after the SSE 200 has been committed travel in-stream as a
  `data: {"error": …}` line (standard proxy convention).
- Provider changes made while the server runs need `/serve off` + `on`
  (settings are snapshotted at launch) — the status text says so.
