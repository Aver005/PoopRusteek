# 2026-11-06 · UI-1: опасные баги TUI и этапы 0–2 отчёта

Дорожка UI-1 релиза шлюза. План: `.docs/research-2026-11/01-ui-critique.md` §5.6,
`04-tui-engine-audit.md`. Снимки: `.dev/research/ui/baseline` → `after-1`.

## Решения

- **Главная — вариант A.** Один скелет `render/layout.rs::Regions` для
  приветствия и переписки: `transcript / attach / dock / rule / input / footer`.
  Нижний край не зависит от содержимого: последняя строка ввода всегда вторая
  снизу. Закреплено тестами `render::tests::the_input_sits_on_the_same_row_…`
  (размеры 60×20…200×60, оба экрана) и `layout::tests`.
- **Подсказки клавиш — в правиле над вводом** (как в макете §5.2), а не в
  подвале: пункт 13 отчёта («слева клавиши») противоречит макету, выбран макет.
  Подвал: `provider · model · mcp · chats · статус` слева, `ctx · время` справа.
- **Сегменты с приоритетом** (`render/segments.rs::fit_segments`): при нехватке
  места часть сначала укорачивается, потом отбрасывается; маркер ошибок
  (приоритет 0) не отбрасывается никогда.
- **Dock** (`render/dock.rs`) открыт, только пока идёт ход фокусного чата,
  суб-агент или цикл GOAL. Постоянные фоновые процессы и таймеры одни его не
  открывают — они в подвале. Высота ≤ 4 строк, остаток — «+N more».
- **Очередь сообщений.** До правки Enter во время хода молча ничего не делал,
  очереди не было. Теперь обычный текст встаёт в `Conversation::queued`, уходит
  по одному на конце хода (`App::send_next_queued`), показан в dock и в правиле.
  Команды (`/…`) и ввод цели во время хода не ставятся в очередь — текст
  остаётся в поле, в статусе подсказка. Esc/Ctrl+C возвращает очередь в поле.
- **Esc в простое** ничего не делает (снимает только выделение и меню). Ctrl+L
  больше не стирает чат: перерисовка и прыжок вниз. Чат чистит `/clear`, выход
  — Ctrl+C.
- **Боковая панель**: `AppState::show_stats_panel: Option<bool>`; `None` — по
  ширине (≥ 140 колонок), `Ctrl+P` ставит явное решение.
- **Глифы**: `[ui] glyphs = auto|unicode|ascii` (`config::GlyphMode`),
  `tui/glyphs.rs`. `auto` → ASCII на Windows, если нет `WT_SESSION`,
  `TERM_PROGRAM`, `ConEmuANSI`. Набор кадра хранится в `thread_local` и
  выставляется в начале `draw_frame`. Рамки `─ │ ├ └ ·` оставлены (есть в CP437).
- **Контраст**: `text_dim` поднят до ≥ 4.5:1 к `bg` и ≥ 3:1 к `user_bg`,
  `tool_bg`, `panel`, `input_bg`, `selection` во всех 10 пресетах;
  `text_soft` слегка поднят, чтобы иерархия dim < soft сохранилась;
  `input_bg` отличается от `bg` не меньше чем в 1.15 раза. Тесты в `theme.rs`.
- **Курсор** ставится в одном месте (`draw_frame` → `Frame::set_cursor_position`);
  ручной `MoveTo`/`show_cursor` убран. Виден и во время хода (для очереди).
- **Паник-хук** ставится в `tui::init()` (после `color_eyre::install()`), сначала
  восстанавливает терминал, потом зовёт прежний хук. Только для паники в потоке
  интерфейса: паники ходов агента ловит `run_guarded`, терминал им трогать нельзя.
- **Подсветка кода** — инкрементальная (`markdown::HIGHLIGHT_PROGRESS`): хранятся
  готовые строки и состояние syntect после последней законченной строки.
- **Тема в кэше сообщений**: `chat::sync_cache_theme` сбрасывает `MSG_CACHE` при
  смене отпечатка темы (`Theme::cache_id`) или набора глифов.
- **Диск вне кадра**: тег сессии берётся из `Conversation::tag`; список сессий
  главной читает фоновая задача (`app/landing.rs`), результат — `AppEvent::LandingSessionsLoaded`.
  `@`-автодополнение — `spawn_blocking` + `AppEvent::AutocompleteReady` с номером
  запроса; пока скан идёт, новые нажатия лишь помечают повторное чтение.
- **Окно подтверждения** (`render/approval.rs`): аргументы переносятся по ширине,
  окно растёт под них (до экрана), прокрутка считается тем же кодом, что и
  отрисовка (`approval_viewport`; для этого в `AppState` добавлен `terminal_cols`,
  `AppEvent::Resize` несёт ширину). Фон под модалкой приглушается
  (`popup::dim_backdrop`).
- `textwrap` в `modals.rs` заменён на `tui/wrap.rs::wrap_words`; из `Cargo.toml`
  не удалён (сделает ведущий).

## Затронуто за пределами «моих» путей

## Найдено по пути

- `refresh_autocomplete` сортировал по `usage.ends_with('/')`, а `usage` для
  файлов — полный путь без `/`: сортировка по сути была по имени. Оставлено
  по имени.
- `accept_autocomplete` звал `Path::is_dir()` (диск на Enter); теперь папку
  отличает `/` в имени подсказки.
- Старый код главной ставил поле на `Rect` высотой 4 независимо от места.
- Блок в `highlight_code` копировал весь код в ключ кэша при каждом кадре.

## О коммитах

Коммиты нарезаны из одного общего дерева: каждый проходит хук на полном
рабочем дереве, но отдельные промежуточные индексы целиком не собираются
(в первых коммитах, например, `render/mod.rs` ещё старый). Собирается и
проходит всё на последнем коммите ветки.

## Что не успел / нужно ведущему

- Живой conhost не снимал: глифы ASCII-режима проверены только тестом
  «в наборе нет небезопасных символов», не глазами в консоли.
- `Cargo.toml`: `textwrap` больше не используется в `src/` — можно убрать при слиянии.
- `AppEvent::Resize` теперь несёт `cols`, если другая дорожка матчит это событие —
  потребуется `..`.

## Ревью UI-1 (review-ui-1.md): правки

Каждый коммит собирается и проходит хук сам по себе (разработка шла по
коммитам, а не нарезкой из общего дерева).

- **M1** `Esc` возвращает очередь целиком: `QueuedMessage { text, chips, named }`,
  чипы встают настоящими вложениями (`InputState::append_restored`), одноимённый
  чип переименовывается, файлы `/attach` возвращаются в полосу. Тесты в `app/queue.rs`.
- **M2** `send_user_text` работает только с файлами сообщения и пишет заметки в
  свой чат; `/attach` снимается в момент Enter. Структурный тест `turn_message`.
- **M3** Один выход очереди: `App::drain_idle_queue` после каждой пачки событий
  (`settle_frame`), для любого чата, что перестал быть занятым (ход, `/compact`,
  отмена). Пути, снимавшие `generation.active`: `finish_turn`, `end_compaction`,
  `cancel_focused_turn`, `/load`, `/import`, `/reset`, `cancel_all_turns` — для
  первых трёх очередь уходит или возвращается, для замены истории возвращается в поле.
  `Esc` в простое с очередью возвращает её; подсказка в правиле и в доке.
- **M4** `Esc` отменяет настройку GOAL (`GoalState::is_setup_pending`), статус
  «GOAL setup cancelled», текст поля цел; плейсхолдер и подсказка говорят, что
  следующее сообщение станет целью.
- **Упавший ход**: `reduce::apply` ставит `queue_paused`, новый ход снимает;
  панель пишет «turn failed…», Enter на пустом поле шлёт следующее, Esc возвращает.
- **`/clear`, `/home`, `/reset`, `/load`, `/import`** возвращают очередь в поле
  (`/reset` теперь чистит поле до `clear_chat_view`, иначе текст пропал бы).
  `/new` очередь не трогает: она остаётся у своего чата, ничего не теряется.
- **Секреты в summary**: `agent/redact.rs` (имена `token`, `api_key`, `password`,
  `authorization`, `secret`; Bearer, `--token`/`--password`, `KEY=значение`,
  `"password": "…"`); маска до усечения; тот же итог показан в заголовке окна
  подтверждения. Ведущий объединит с `secrets/redact.rs`.
- **Сканы `@`** (`app/file_scan.rs::ScanTracker`): один скан за раз, запросы
  сливаются в самый свежий, одинаковый запрос не повторяется, устаревший ответ
  не показывается; трекер в `AppState`, поэтому сброс меню не теряет идущий скан.
  Отмены задачи нет (`spawn_blocking` не отменить) — это коалесценция.
- **Прокрутка при смене высоты**: `scroll_after_height_change` пересчитывает
  смещение по изменению высоты переписки перед кадром (`settle_frame`); верхняя
  строка стоит на месте, у низа — приклеено. Тесты на функцию и на `render_chat`.
- **Ctrl+L**: `needs_full_redraw` → только `terminal.clear()`.
- **Ширина в панели**: `UnicodeWidthStr`, `clip_cells`.
- **Глифы**: onboarding, themes, search, подпись «always allow» — через
  `tui::glyphs`; тест-сканер исходников и тест отрисовки всех сцен в ASCII.
- **Подсветка**: в ключ добавлен номер блока; блок без законченной строки не
  кэшируется (ключ менялся на каждый токен и забивал кэш).
- **m9** подсказка `Ctrl+P` убрана с приветствия; Ctrl+P объясняет в статусе,
  почему панели нет. **m12**: `truncate(_, 0)`, `scroll` без переполнения u16,
  `error_count` не гасится постановкой в очередь.
- **UI-2**: карточка и сессии на всю ширину, подсказки у поля ввода, `ctx` после
  первого сообщения, «+N more agents» на строке очереди (или своей строкой
  дерева), заголовок окна подтверждения с итогом и красными опасными словами
  (`rm`, `sudo`, `--force`, `-rf`…), перенос по границам слов без потерь.

### Опровергнутое

Ложных находок не нашёл: каждую воспроизвёл по коду. Уточнения: в m3 «флаг
scanning сбрасывается ветвью команд» верно только для прежней версии (флаг жил
в `AutocompleteState`, который сбрасывали Esc/Enter); теперь трекер отдельный.
`attached_files` общий и при смене фокуса не сбрасывается (`grep` по
`multichat.rs` — ни одного упоминания), так что M2 подтверждён.

### Отложено, с причиной

- **m11 очередь только в памяти.** Нужно поле в `Session` или отдельный файл
  черновика; `Session` меняет ветка шлюза (`route_state`), правка формата здесь
  дала бы конфликт. Сейчас очередь возвращается в поле при Esc/Ctrl+C/`/clear`/`/load`;
  при убийстве процесса теряется.
- **`expand_file_mentions` на цикле событий.** Тот же путь, что у обычного Enter
  (читает файлы по `@путь` в тексте); вынос в `spawn_blocking` меняет порядок
  отправки и заслуживает отдельной правки.
- **Живой conhost** по-прежнему не снимал.

### Слияние с `feature/gateway-release`

Слилось без конфликтов (`route_state` в `capture.rs`, маскировка токена в
онбординге — автоматически). `secrets::redact` уже была в ветке, поэтому
`agent/redact.rs` теперь сначала зовёт её, потом свои правила по именам.
Проверено после слияния: fmt, clippy `-D warnings`, 1774 теста; четыре mock-сценария
(`edits-and-writes-files`, `tracks-a-plan`, `runs-dsml-calls`,
`recovers-from-malformed-call`) — по 2/2; снимки `.dev/research/ui/after-2`
(37 кадров), просмотрены глазами: главная, подтверждение, док с очередью и
«+5 more agents», работа в темах и ASCII.
