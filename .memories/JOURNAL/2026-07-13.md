# 2026-07-13 — Prompt diet + the hint-displacement bug

## Trigger

Owner: «системный/первый промпт слишком раздутый, DeepSeek из-за этого быстрее
галлюцинирует — изучи и предложи варианты». The study confirmed the bloat
(~27 KB fixed overhead ≈ 6–7k tokens before skills/MCP) **and** surfaced a
wire-level CRITICAL that explains the "hallucinations" better than size does.

## Part 1 — CRITICAL: semantic hint displaced the user's message

Chain: `run_agent_loop` pushed the RAG hint as `Role::System` **after** the
newest user message → `split_system_prompt` only extracts the *first* system
message → `build_prompt` on a continuing session sent **only
`messages.last()`** → whenever the hint fired, the request was
`### USER INPUT\n[Hint…]` and the user's actual text **never reached the
server** (first send: user text mislabeled into `### LOCAL MEMORY`, hint posed
as USER INPUT). The model answered the hint about skills/MCP tools instead of
the question — externally indistinguishable from hallucination, and it fired
exactly when semantic matching *worked*.

Fix (all in `src/provider/prompt.rs`, `src/provider/deepseek/stream.rs`,
`src/agent/runner.rs`):
1. Hint inserted **before** the user message (`rposition` + `insert`).
2. `build_prompt` reworked around a **tail batch**: everything after the last
   assistant message goes out, per-piece sections `### NOTE` / `### USER
   INPUT` / `### TOOL RESULT: {name}` — a user message can never be displaced
   again, regardless of message ordering.
3. `should_reset` now uses role-aware `is_first_conversational_send` (a hint
   riding along with the first user message no longer masks a fresh
   conversation — without this, a `/new` on a reused provider would have
   continued the stale remote session).
4. `FORMAT_REMINDER`: every non-empty send ends with a one-line RU anchor
   restating the `<tool_use>` format (~60 tokens/turn; recency > primacy for
   weak models; cheap because DeepSeek holds history server-side).

Regression tests: `hint_before_user_keeps_user_input_last`,
`trailing_system_note_never_displaces_user_input`,
`first_send_renders_hint_as_note_not_memory`,
`first_conversational_send_ignores_system_notes`,
`empty_user_content_on_later_turn_sends_nothing`.

Note: anthropic/openai/gemini compat layers were never affected (they map
system messages properly); this was DeepSeek-flat-prompt-specific. The RAG
layer itself (matching, ranking, thresholds, `render_hint`) is untouched —
no MRR eval needed.

## Part 2 — Prompt diet

Fixed overhead was ~27 KB before skills/MCP: base 10.8 KB + tools 8.2 KB +
~8 KB formatted builtin defs, with the same topics explained 2–3× and two
direct contradictions (D3 "one action per turn" vs "batch independent reads";
"never assume — always ask" vs "don't ask if you can decide"). Also a `最少`
CJK artifact mid-Russian in base.prompt.md.

- `base.prompt.md` 10.8 → **3.7 KB**: 7 ranked rules replace 7 directives +
  4 protocol sections; tool-syntax duplicate deleted (single source =
  tools.prompt.md); `<thinking>` kept but compressed to 2 lines (the TUI's
  `tool_parser` really does strip it — it's the poor-man's reasoning channel
  for non-reasoner models, deliberately not removed); contradictions resolved
  (reads batchable, edits read-first; ask only when the choice is genuinely
  the user's).
- `tools.prompt.md` 8.2 → **2.8 KB**: one canonical `<tool_use>` example +
  rules; 110-line background/interactive tutorial compressed to 3 bullets
  (the details already live in the tool schemas — `shell_input` enumerates
  every key, `question` describes both modes); the 60-line RU question
  section deleted outright.
- Prose unified to RU (machine artifacts — tool schemas, deferred-MCP
  summary, wire labels — stay EN).
- **Skills injection modes** (`[skills] injection = auto|full|summary`,
  `SkillInjectionMode`, default auto, budget `AUTO_FULL_BUDGET_BYTES` = 8 KB):
  oversized enabled-skill content becomes a `slug — description` list; the
  model loads a skill on demand (`skill` tool) and the per-turn semantic hint
  names the match. Unbounded prompt growth from enabled skills is gone.
- **MCP resources** itemization moved behind the same deferred gate as tool
  schemas (count-only when deferred; there is no resource-read path in the
  agent loop today anyway).
- **Guardrails**: `system_prompt.assembled` debug-log line (per-section
  bytes) + byte-budget tests (`prompts.rs`: base < 5000, tools < 4500;
  `tools/registry.rs`: builtin defs < 10000) so the diet doesn't silently
  regress.

Net: fixed prompt overhead ~27 KB → ~14.5 KB (of which 8 KB is builtin tool
schemas — candidate for a future deferred-builtin pass, deliberately not done
now to keep scope).
