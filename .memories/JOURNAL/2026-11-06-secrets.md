# 2026-11-06 — дорожка SECRETS: хранение секретов и открытый слоёный конфиг

Ветка `t3/0143cc81`. Код: `src/secrets/`, `src/config/{paths,lock,fields,describe,layers,load,write,migrate,startup,protect}.rs`,
`src/cli/{secrets,doctor}.rs`, `src/commands/defs/{secrets,doctor}.rs`. Описание для людей: `.docs/secrets-and-config.md`,
пример конфига: `config.example.toml`.

## Что сделано

- **Хранилище.** `SecretStore` (бэкенд `keyring`, кэш на время процесса, `set_verified`: запись → чтение мимо кэша →
  сравнение). Длинные значения режутся на куски по 900 байт с заголовком и суммой (`psec1:N:sum:`), потому что
  Windows хранит пароль в UTF-16 и держит 2560 байт на запись (проверено по исходнику `windows-native-keyring-store`:
  `validate_password` кодирует в UTF-16). Таймауты 5 с на чтение и 10 с на запись, каждый вызов в своём потоке.
  `Secret` без `Display`, `Debug` = `<secret>`. Ошибки называют имя секрета, не значение; ошибки `keyring` разбираются
  по виду (у `BadEncoding` в `Debug` лежат байты значения).
- **Резолвер.** `SecretResolver` из контракта, реализация `StoreResolver`: `keyring:`, `env:`, `cmd:` (без оболочки,
  10 с, без окна на Windows), `file:` (на unix права 0600), `none`. Проектные аккаунты: `cmd:`/`file:` запрещены, ключ
  выдаётся только подтверждённому хосту (`[secrets.bindings]`, `secrets bind`).
- **Слои.** Общий `~/.pooprusteek/config.toml` и `.pooprusteek/config.toml` (вверх до корня git, вне git — папка
  запуска). Слияние по ключам, массивы по `id`/`name`. Запрещённое в проекте → слой не применяется целиком, причина в
  заметке при запуске и в `doctor`. Карта «ключ → слой» в `Config.source.origins`.
- **Запись конфига.** Разница «загружено → стало» через `toml_edit` под блокировкой `config.toml.lock`; комментарии,
  порядок и незнакомые ключи остаются. Повреждённый файл (TOML или тип) не затирается. `--config` закреплён: запись
  идёт в него. Значения из проектного слоя в общий файл не попадают.
- **Миграции.** Старые открытые ключи → хранилище с проверкой; `[[providers]]` → `[[accounts]]` один раз с копией
  `config.toml.pre-gateway`; старый конфиг и старая папка данных переносятся копированием. После запуска, где все
  ссылки читаются, ключи в копии затираются. Фоновая добивка после сохранения (`kick_background_migration`).
- **Утечки.** История ввода (`is_sensitive_input` + очистка при загрузке), маска токена в онбординге, редактирование
  журнала отладки и трасс (`secrets::redact`), `redact_value` DeepSeek, отказ `read_file`, охрана `safe_write`,
  `/wipe` (хранилище, MCP, файлы конфига), `/logout` (удаление записи), права 0600 на unix для конфига, истории и
  журнала, ошибки TOML без значений (`config::describe`), `Debug` без секретов.
- **Команды.** `pooprusteek secrets list|set|rm|test|bind`, `pooprusteek doctor [--json] [--origins]`, `/secrets`,
  `/doctor`. Значение не идёт через argv: stdin или скрытый ввод в терминале.
- **Встраивание шлюза.** `Config.{gateway,accounts,routes,roles}`; `deny_unknown_fields` на `Account`, `Route`,
  `GatewaySettings`, `GatewayConfig`; проверка `schema` в `validate()` и при загрузке (`> 1` — отказ). Старый `Config`
  по-прежнему игнорирует лишние ключи (тест).

## Отклонения от задания и решения

1. **`[[providers]]` продолжает писаться.** Задание: «больше не пишется». Пока `/providers` (GW-TUI) работает со
   списком `config.providers`, прекращение записи теряло бы добавленные записи. Миграция один раз зеркалит записи в
   `[[accounts]]` (общая запись в хранилище), старый список остаётся читаемым и живым. `doctor` предупреждает о
   записях, которых нет в аккаунтах. Когда GW-TUI переведёт `/providers` на `apply_edit`, запись `[[providers]]`
   нужно выключить одной строкой (`skip_serializing_if` на `Config.providers`).
2. **Секреты старых полей разворачиваются при загрузке в память**, а не при сборке адаптера: так не меняются
   потребители (`provider/*`, `server/*`, `app/*`), которые вне моих границ. Контракт `SecretResolver` для аккаунтов
   шлюза работает как задумано.
3. **Проектный `config.local.toml`** (из карты) не делался: решение владельца говорит о двух слоях.
4. **Открытый `[server] api_key`** переносится в хранилище так же, как остальные; на сервере без хранилища он
   остаётся в файле, `doctor` это показывает.
5. **`/secrets set <имя> <значение>` показывает значение на экране**, пока человек его печатает: маскированный
   модальный ввод — это `src/tui/**` и `src/app/keys/**` (GW-TUI). Строка не попадает в историю. Для скрытого ввода есть
   CLI. Отложено: модалка с маской.
6. **JSON Schema** отложена: `schemars` — новая зависимость, а писать схему вручную без проверки соответствия
   структурам будет дрейфовать. Когда зависимость разрешат: `schemars` + тест «схема соответствует структурам» +
   `#:schema` в шапке.
7. **Показ адреса при первом запросе проектного аккаунта** (диалог) — на стороне GW-TUI; данные: `Config::trust_context()`,
   `SecretError::HostNotTrusted`, `config::bind_secret_host`.
8. **Перезагрузка проектного слоя при `/cd`** не делалась.
9. **Модель и семантический индекс** при переносе папки данных не копируются (перекачиваются), логи тоже.
10. **Права ACL на Windows** не выставляются: файл наследует ACL профиля; 0600 — только unix.
11. `Layer::Builtin` убран: значения «по умолчанию из кода» просто отсутствуют в карте источников.

## Изменения контрактов (для интегратора)

- `Config::path()` теперь «куда пишется» (`--config` или общий файл), а не папка `dirs::config_dir()`;
  `Config::global_path()` — всегда общий файл. В тестах `path()` указывает во временную папку.
- `Config::data_dir()` по умолчанию `dirs::data_local_dir()/pooprusteek`; до успешного переноса `main` выбирает старую.
- Новые поля `Config`: `gateway`, `accounts`, `routes`, `roles`, `secrets`, служебное `source` (serde skip).
  Литералы `Config { … }` без `..Default::default()` не собираются.
- `CommandResult::Detached(Box<dyn FnOnce() -> String + Send>)` + ветка в `app/keys/dispatch.rs` (работа на
  `spawn_blocking`, ответ — событием `UpdateStatus`).
- `Account`, `Route`, `GatewaySettings`, `GatewayConfig` — `deny_unknown_fields`; ручной `Debug` у `Account`, `Credential`.
- Правки в чужих файлах (точечные): `app/keys/dispatch.rs` (одна ветка), `app/mod.rs` (`execute_wipe`, `wipe_roots`),
  `commands/mod.rs` (вариант и две регистрации), `tui/render/onboarding.rs` (маска), `main.rs`, `gateway/types.rs`.
