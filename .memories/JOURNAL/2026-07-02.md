# 2026-07-02

## Full-codebase audit → 3-wave stability/perf refactor

Goal: run a from-scratch audit of the whole tree, then fix everything CRITICAL and as much
MAJOR as the day allows, without regressing behavior. Landed as a single commit, `bad8011`.

### Morning: full audit (5 parallel auditors)

Five parallel deep-reading passes over disjoint slices of the tree (streaming/provider,
MCP, app/event-loop, tools/background, TUI/render + commands/misc) plus a synthesis pass
that merged, deduplicated, and severity-ranked the findings into one digest:
`reference/AUDIT-2026-07-02.md`. Found **7 CRITICAL**, ~30 MAJOR (most fixable same-day,
some deliberately deferred), and a handful of ACCEPTED trade-offs.

Headline criticals: streaming was never actually live (the SSE stream was fully drained
before the caller saw anything, and the 120s idle guard watched an already-full channel);
the MCP manager mutex was held across a network `.await`, so one slow MCP call froze the
entire TUI; the GOAL evaluator ran a full LLM completion **inside** `handle_event` on the
`select!` loop task; `/goal` was unreachable (registered with a leading slash, dispatch
strips it before matching); `--acp` panicked on the first prompt (nested Tokio runtime);
the render pipeline re-parsed markdown/syntect over the whole transcript on every event
with no cache, plus an unbounded event queue; MCP stdio never drained child stderr and had
no JSON-RPC `id` correlation, so a chatty server could deadlock or desync every response.

### Afternoon/evening: 3-wave refactor

**Wave 1** — four agents in parallel (MCP hardening, quick-win majors, tools/background
fixes, docs) plus the lead handling the streaming pipeline directly (highest-risk, most
cross-cutting change: spawning `complete_stream` as its own task in both `runner.rs` and
`sub_agent.rs`, adding real reqwest timeouts, stripping the stray `gzip` header, rewriting
`SseLineBuffer` byte-based with a 4MiB cap, making retry backoff saturating).

**Wave 2** — lead handled `app/`-core changes directly (GOAL evaluator off the loop via
`spawn_goal_evaluation`/`GoalEvaluationDone(GoalEvalOutcome)`; the `PendingInteraction`
queue replacing the single-slot approval waiter; `ChatMessage.ui_only` splitting
model-visible history from UI chrome; unified `Conversation` reducer methods
(`begin_assistant_message`/`append_chunk`/`discard_empty_assistant`/`finish_turn`) so the
focused and background event paths stopped duplicating and diverging), while a second
agent built the TUI render-cache fix (drain+dirty-flag `run_loop`, per-message
thread-local markdown/syntect cache in `tui/widgets/chat.rs` keyed by a content
fingerprint with 4096-entry eviction, cached token estimates).

**Wave 3** — a dead-code sweep: removed `parse_sse_event`/`ParsedSSEEvent` (a fully dead
"enhanced" typed SSE parser with zero call sites), ~12 dead structs/consts in
`provider/types.rs`, 4 dead endpoint consts, 2 dead settings methods, `has_tool_calls`,
`AppState.error`, `GenerationState.last_think_fragments`, `CommandResult::NeedsAgent`,
unused theme fields, `BackgroundHandle.id`, `SpawnOutcome.status/interactive`, `API_BASE`.
Deliberately kept: ~26 unused `DeepseekProvider` REST wrappers, parked in their own
`#[allow(dead_code)]` impl block pending the planned `deepseek.rs` split.
